ACS throttling currently stops new API claims, but queued plain and composed email commands continue to hit ACS, return transient failures, and later re-enter the claim queue. A second throttle report can replace a longer window with a shorter one.

To close this out:
- Share one durable ACS throttle window across the Notifications API and every email-service instance. A 429 with `Retry-After` extends it to the reported reset instant; later shorter reports cannot shorten it. Keep the existing `EmailServiceRateLimitCommand` `data` and `source` wire fields readable by older consumers.
- Both plain and composed API claims stop while that window is active. Already queued plain and composed sends wait rather than reporting transient failures or calling ACS repeatedly. Once it expires, each email has exactly one accepted ACS send within 45 seconds of expiry; no throttled command publishes a failure result.
- A window remains in force when the API and an email-service instance restart; another instance must honor a 429 promptly too (at most one further ACS attempt per instance after the first 429 and before expiry). Overlapping 30-second and 5-second windows still exclude sends until the longer window expires.
- Without a throttle signal, the existing plain sending path still delivers email.

The repository lives at `/app`. The API owns PostgreSQL-backed notification claims; the shared timeout is stored in the latest `notifications.resourcelimitlog.emaillimittimeout` row and extended through `notifications.set_email_timeout(timestamptz)`, which both API and workers must use. Wolverine transports commands through the Azure Service Bus emulator. Existing `EmailServiceRateLimitCommand` messages containing only `data` and `source` remain consumable, as do messages with an optional `resetTime`. Email-service workers use the configured ACS connection string. Docker is unavailable inside the solver container; PostgreSQL, SQL Server and the ASB emulator run as sidecars. The email service receives the shared PostgreSQL connection string through `EmailThrottle__ConnectionString` (the .NET configuration key `EmailThrottle:ConnectionString`); keep normal service configurations usable. Build from `/app` with `dotnet build components/email-service/src/Altinn.Notifications.Email -p:NuGetAudit=false` and `dotnet build components/api/src/Altinn.Notifications -p:NuGetAudit=false`.
