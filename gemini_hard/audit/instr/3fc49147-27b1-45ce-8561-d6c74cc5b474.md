Give Starlette applications stable, inspectable lineage for every inbound HTTP and WebSocket message, including messages transformed by middleware or consumed during failures. Callers can trace derived messages and parsed artifacts back to immutable connection-local records without affecting normal protocol behavior.

Every validated server message receives exactly one immutable identity in receive order, and Request and WebSocket `receive_event` expose that event without duplicate allocation. `inbound_history` returns an insertion-ordered immutable snapshot that never changes after capture. One ledger follows a connection through application policy, routing, mounted scopes, authentication, endpoint execution, and handled exception dispatch, while concurrent connections remain isolated. Forwarded, consolidated, and synthetic messages retain ordered parent identities for exactly the server records that caused them, including cached replay, terminal messages, disconnects, and rejected size-limit chunks. Form fields expose their contributing identities through `lineage_for`, and UploadFile exposes them through `inbound_event_ids`, always referring to the same history visible to handlers and authentication backends. Authentication inspection consumes nothing, creates no events, and cannot affect subsequent HTTP or WebSocket reads. Successful WebSocket validation precedes recording, while parsing, limit, and disconnect failures preserve a completed immutable history for the configured handler without changing existing exception selection or outcomes. Lineage observation preserves request chunks, cached messages, protocol states, routing metadata, and handler selection.

When middleware caches a multi-chunk body, the handler sees one consolidated child with the original records as ordered parents. A chunk-based size rejection exposes prior accepted events followed by one rejected event, while pre-receive content-length rejection records nothing. WebSocket connect, data, and disconnect grow lineage without changing the protocol state machine. A routed multipart handler can match every UploadFile contribution to its Request snapshot, including before a handled malformed-input failure. Authentication before mounted routing leaves pending input untouched, and the endpoint later sees the same existing event objects.
