Add opt-in semantic validation for DHCPv4 values, packets, transport conversations, and netboot configuration while preserving existing permissive behavior. Callers receive complete, deterministic diagnostics before invalid data becomes observable. Validated packet modification is transactional.

Validation reports are immutable, repeatable, and ordered by packet field then numeric option code, with stable paths, codes, severities, and descriptive messages. Every supported option representation, including AutoConfiguration, Duration, IP, IPs, Uint16, OptionCodeList, and OptionGeneric, enforces its code-sensitive wire and contextual semantics without changing serialization, formatting, caller ordering, or permissive handling. Stored Options use concrete decoders, continue after decoding failures, and aggregate every issue deterministically. DHCPv4 packet validation combines header, required-option, option-value, and cross-option diagnostics without mutating packet data. Strict parsing succeeds only when framing and semantics are valid, whereas FromBytes remains semantically permissive. ApplyValidated applies modifiers in caller order but publishes no changes unless the final packet validates. One ValidationPolicy produces matching classifications at validated client, server, and netboot boundaries; invalid client conversations retain prior replies, invalid server datagrams suppress only their handler call, and invalid netboot replies never produce configuration. The dhcpv4 package exports DefaultValidationPolicy, Options.Validate, DHCPv4.Validate, and ValidationError.Error; server4 exports WithValidation(policy), returning ServerOpt.

A packet with invalid header state and several invalid options returns one repeatable report ordered by field and numeric option code. Missing required options and inconsistent lease, renewal, and rebinding timer ordering each produce packet diagnostics. A validated modifier sequence introducing an invalid indexed address fails atomically, leaving earlier changes unobservable. A semantically invalid framed datagram remains decodable through legacy parsing but stops a caller-selected validated client conversation. Client, server, and netboot boundaries using one policy report matching issue paths before exposure. After suppressing an invalid datagram, a validating server continues and delivers the next valid packet once.
