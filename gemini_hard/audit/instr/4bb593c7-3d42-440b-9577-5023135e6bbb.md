# Goal

Implement tenant-wide, durable `StorageBytes` accounting for presigned uploads across two replicas sharing PostgreSQL, Redis and S3. Current checks do not reserve capacity.

# Requirements

1. `POST /api/v1/files/upload-url` reserves the declared positive byte count atomically against a tenant's configured storage limit; requests that exceed it return 507. Six concurrent 3 MiB requests against 10 MiB grant only three. Holds appear in `GET /api/v1/files/usage` as `{ "storageBytes": <integer> }`.
2. `POST /api/v1/files/{id}/finalize` replaces the hold with the S3 object's actual size, once only. Objects larger than their reservation return HTTP 400, are removed, and release capacity. Concurrent finalizations produce one success; duplicate finalizations return HTTP 409. Files already finalized before upgrading contribute to usage on the first request.
3. The upload deadline is the presigned URL lifetime; configure `Files:UploadUrlTtlSeconds` for short lifetimes (20 seconds). Expired holds release capacity within 30 seconds. Late finalize returns HTTP 409 or 404, and orphan cleanup removes the uploaded S3 object. Simultaneous finalize and orphan purge must leave file state, object and usage consistent, even with a locked file row.
4. `DELETE /api/v1/files/{id}` retains its soft-delete behavior and cannot strand bytes when racing with finalize. The deleted-file purge removes retained objects and returns their bytes once, even if two replicas run it simultaneously. Direct uploads through the metered storage service also reserve and commit durable capacity and return capacity on removal.
5. Redis data loss or a 20-second outage must never admit an upload beyond the limit or erase accounted bytes; usage equals stored files plus unexpired holds within 30 seconds of Redis recovery, without requiring an API restart. Outage rejection is acceptable if Redis-dependent components fail. Replicas without Redis still share storage accounting.

# Keep compatible

The tenant `POST /api/v1/identity/token/issue` login and existing presigned PUT, file finalize, metadata (`GET /api/v1/files/{id}` with `sizeBytes` and `status`) and delete flows continue working. Only `StorageBytes` is in scope, not other quota resources.

# Environment

Work in `/app` (.NET 10; no Docker). Services: PostgreSQL `postgres:5432` (`sd`, `app`/`app`), Redis `redis:6379`, MinIO `minio:9000` (bucket `files`). Build `src/Host/FSH.Starter.Api` and `src/Host/FSH.Starter.DbMigrator` with `dotnet build -p:NuGetAudit=false`. Set `DOTNET_ENVIRONMENT=Development` and `DatabaseOptions__ConnectionString`; run `dotnet run --project src/Host/FSH.Starter.DbMigrator -- seed-demo`, then `dotnet run --project src/Host/FSH.Starter.Api`. Configure `QuotaOptions__Enabled=true` and `QuotaOptions__Plans__{free,pro}__StorageBytes=10485760` (set both keys separately); seeded `acme` uses pro. Accounting must also work for other tenants (e.g. seeded `globex`).
