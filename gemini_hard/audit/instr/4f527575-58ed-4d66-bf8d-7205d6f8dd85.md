# Fenced daemon handover

Make two `dagster-daemon` replicas safe on shared PostgreSQL during rollouts and after suspended-leader lease expiry. Change `/app/python_modules/` so daemon, storage, gRPC and GraphQL agree on the active replica.

- Only one replica acts as leader; after it is suspended the standby can dequeue new work within 30 seconds. Resuming the old replica must not duplicate launches or create sensor runs using its expired leadership generation.
- A run already committed as `STARTING` when its leader is suspended must start within 45 seconds under its successor, execute once, and not execute again when the former leader resumes. This includes a predecessor blocked on a PostgreSQL `run_tags` table lock after committing `STARTING` but before launching the worker.
- With two replicas and `max_concurrent_runs: 2`, ten queued runs complete with one execution per run and at most two running simultaneously. Concurrent dequeues of the same queued run cannot create a second execution, including when a PostgreSQL row lock on that run delays the dequeue.
- A successfully canceled `QUEUED` run stays `CANCELED` without launching, including when a previously read queued run subsequently emits a delayed `STARTING` event; queued-run termination continues to return its usual GraphQL success response.
- Concurrent sensor evaluations yielding `RunRequest(run_key="k")` persist at most one run per sensor, repository and key. Other sensors and repositories may use the same key; repeated evaluation of an existing key keeps working.
- Direct gRPC `StartRun` for an already launched or canceled run reports failure and forks no worker. A valid first `StartRun` still succeeds. Daemon launch arguments serialized as `ExecuteExternalJobArgs` carry `daemon_owner` (string) and `daemon_epoch` (integer); `StartRun` rejects an expired owner/epoch pair even if the run has not started.
- Each GraphQL `daemonHealth.daemonStatus(daemonType: ...)` result exposes `activeReplicaId` for the active daemon, changes it after failover, and retains `daemonType`, `healthy` and `lastHeartbeatTime`. Run status and tag queries remain available.

Repository: `/app`; dependencies: `/app/.venv`. PostgreSQL: localhost:5432, `postgres`/`postgres`. As `agent`, start PostgreSQL with `/usr/lib/postgresql/15/bin/pg_ctl -D /home/agent/pgdata -l /home/agent/postgres.log start`, or use `sudo service <name> start|stop|restart|status` for installed services. Run checks from `/app` with `/app/.venv/bin/python -m pytest`. Docker is unavailable.
