Let Goss validate that a declared set of installed packages has a complete, version-compatible runtime dependency closure. Relationship data must reflect the selected host package manager while supporting alternatives, virtual capabilities, cycles, recursive configuration, and concurrent validation. Existing package-only configurations must remain observationally unchanged.

The `github.com/goss-org/goss/system` package exports `Package`, `PackageRelationshipReport`, `PackageRequirement`, and `PackageCapability`; each isolated report carries Name, Version, ordered Requirements with Alternatives, and Provides whose capabilities retain Name, Operator, and Version. DebPackage, AlpinePackage, PacmanPackage, RpmPackage, and NullPackage relationships preserve their native required-dependency, alternative, version, provider, and error semantics while excluding recommendations, conflicts, optional dependencies, installation metadata, and internal query artifacts from mandatory closure. NullPackage relationship inspection returns the existing unavailable-manager error and no usable report. Closure succeeds exactly when every reachable mandatory relationship from an installed member has one compatible installed provider; external providers may satisfy capabilities without becoming traversal roots, and every edge has one deterministic result. Unresolved relationships produce failing TestResult values identifying the requiring package, capability, and constraint, while query failures remain distinct. The `github.com/goss-org/goss/resource` package exports `PackageSet` with Title, Name, Members, Closed, RetryCount, RetryDelay, and Skip, plus `PackageSetMap`, mapping strings to package sets; JSON, YAML, rendering, and recursive replacement preserve map-key identity and complete-resource semantics. Each ValidateResults invocation uses one immutable relationship snapshot across concurrency, repeated edges, and policy-controlled retries, without sharing observations with later invocations. Ordinary installed-and-versions packages retain loading, validation, retries, rendering, JSON properties and grouping, exit classification, and automatic or explicit manager selection; `github.com/goss-org/goss/util` exports `PackageSnapshotPolicy`, `PackageSnapshotPerRun`, `PackageSnapshotRefreshFailed`, and `WithPackageSnapshotPolicy`.

A recursively overridden package-set validates a transitive dpkg chain using the later identity and normalized alternatives. Concurrent package sets resolving one virtual capability observe one provider report and produce compatible outcomes within an invocation. An apk query failure remains an error through retry and graph evaluation rather than becoming partial closure. An rpm virtual provider satisfies an epoch-aware requirement only when compatible, with diagnostics retaining the capability and concrete provider.
