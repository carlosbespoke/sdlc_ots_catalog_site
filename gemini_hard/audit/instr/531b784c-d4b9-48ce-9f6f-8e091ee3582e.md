# Team events across replicas

A team subscriber attached to one backend process currently misses changes handled by another. Reconnecting also loses changes, and an open subscription can keep exposing team data after its member has been removed.

## What we need

- In `packages/hoppscotch-backend`, make committed root-collection creation and reorder, team-request creation, team-environment creation, and membership role updates visible to team subscribers on every backend replica within 2 seconds. Concurrent environment creations each appear once in the stream; rejected collection creation emits none.
- Add GraphQL subscription `teamEventStream(teamID: ID!, afterSequence: Int = 0): TeamEventMessage!` with `sequence: Int!`, `teamID: ID!`, `topic: String!`, and `data: String!` (JSON of the existing topic payload). Its per-team sequences start at 1, advance without gaps or duplicates in commit order, and agree across replicas. `afterSequence` is exclusive: replay all subsequent events in order, then continue live without a replay/live duplicate. Invalid negative cursors are refused.
- Successful writes survive a backend SIGKILL and a 20-second Redis outage or restart with Redis emptied; Redis availability must not block mutations. Live and resumed subscriptions recover within 30 seconds of Redis returning. A killed replica's subscriber can reconnect to another replica and replay committed changes within 5 seconds.
- On member removal, an affected collection subscription and event-stream subscription on different replicas terminate with an error within 5 seconds, receive no later team events and cannot resume the stream. This includes a reorder started before revocation but committed afterwards. On team deletion, an affected event-stream subscription terminates with an error within 5 seconds and cannot resume.

## Keep working

Existing GraphQL subscriptions `teamCollectionAdded`, `teamRequestAdded`, `teamEnvironmentCreated`, `teamMemberUpdated` and their current payload fields remain usable. Existing team creation and collection/request/environment creation remain usable through GraphQL.

## Setup

The working tree is `/app`; build from `/app/packages/hoppscotch-backend` with `corepack pnpm run build`. PostgreSQL and Redis are installed locally; start them with `sudo service postgresql start` and `sudo service redis-server start`. PostgreSQL's `postgres` account password is `postgres`. The backend reads `DATABASE_URL`; use Prisma migrations for schema changes. No Docker daemon is available inside the agent container.
