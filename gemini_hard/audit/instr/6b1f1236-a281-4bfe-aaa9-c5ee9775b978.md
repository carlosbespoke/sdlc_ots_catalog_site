Hertz lacks configurable adaptive write-pressure control for large and streaming HTTP messages. Implement bounded buffering without changing wire bytes, and expose pressure state across transports and every HTTP exchange. With no policy, preserve existing buffering, flushing, errors, trace ordering, and behavior.

Pressure-capable writers must count accepted bytes once and report pending bytes, peak pending bytes, relief count, and terminal failure deterministically after every operation. Standard, netpoll, and generic network writers must count logical accepted bytes once, including bufiox-backed output, pooled small allocations, and borrowed large binary writes. On standard connections, crossing the high watermark triggers ordered relief to at most the low watermark. Output below the high watermark stays pending until explicit flush or later relief. Every generic-writer relief outcome clears pending accounting. Failures retain transport classification through an unwrap-compatible PressureError.

HTTP/1 may relieve only between complete headers, bodies, chunks, terminal chunks, and trailers. Preserve bytes, order, framing, flush visibility, and single finalization. Successful relief preserves pooling and keep-alive eligibility. Terminal failure poisons the exchange, retires the connection, and cannot leak bytes into another exchange.

Validate client and server policies independently before use. Client rejection leaves prior behavior intact. Publish each exchange's final snapshot through HTTPStats without reordering events. Request and response streams observe their respective complete framing units.

Package github.com/cloudwego/hertz/pkg/network exports the pressure types and constructor below; server exports WithWritePressure, client exports Client.SetWritePressure and NewClient, and traceinfo exports HTTPStats.WritePressure.

Large fixed requests may cross standard-writer pressure repeatedly while preserving framing and connection reuse. A netpoll streaming failure returns the normalized cause and prevents pooling. An unconfigured server preserves response bytes, flush timing, and trace order. Borrowed-slice chunked responses relieve only between chunks, finalize ordered trailers once, and remain keep-alive safe. Response relief failure closes the connection, records its cause, and prevents another request dispatch.
