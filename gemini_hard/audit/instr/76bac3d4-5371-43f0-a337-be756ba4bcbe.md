Skupper lacks interoperable optimistic preconditions for connector mutations on Kubernetes and filesystem platforms. Implement opaque logical connector identities that can be obtained and supplied to a later create, update, or delete to avoid changing stale state. Invocations without identities must retain current behavior.

Make identities stable across serialization, map ordering, status, transient metadata, and backend representation, but change them whenever the effective ConnectorSpec changes. Reject malformed or unsupported identities before command execution or waiting causes side effects. Ordinary SkupperCommand implementations must continue through ConfigureCobraCommand unchanged.

Expose precondition input as `--precondition` on create, update, and delete, and identity output as `--identity` on generate and status. Unrelated commands expose neither. Compare the latest available state at the mutation boundary and leave newer state untouched on mismatch. Keep ErrPreconditionFailed distinguishable from native not-found, storage, and Kubernetes API conflict outcomes. Its PreconditionError must expose the operation and resource context. Identity output is read-only and must interoperate with later mutations on both platforms.

The precondition package `github.com/skupperproject/skupper/internal/cmd/skupper/connector/precondition` provides ConnectorPrecondition, ParseConnectorPrecondition, PreconditionForConnector, PreconditionError, ErrPreconditionFailed, and ErrInvalidPrecondition; `github.com/skupperproject/skupper/internal/cmd/skupper/common` provides PreconditionedCommand; and `github.com/skupperproject/skupper/pkg/apis/skupper/v2alpha1` provides NewConnector.

If a connector appears after validation but before create, either backend must reject the stale absence expectation without overwriting it. If ConnectorSpec changes after inspection, conditional update or delete must preserve the newer resource on both platforms. Status identities remain usable after formatting or ignored metadata changes. Generate identities support conditional creation unless logical state intervenes. Without identity options, preserve platform defaults, validation, persisted shape, output, warnings, errors, and waiting behavior.
