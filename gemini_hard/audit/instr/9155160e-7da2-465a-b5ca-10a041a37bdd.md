Our results store is a ParquetDB dataset (the library is checked out in /app) filled from our v1 exports. The v2 exports renamed some fields: `e_form` is now `formation_energy`, `magmom` is now `total_magnetization`, and the nested `sample` record is now `specimen`. On a copy, `rename_fields` leaves the new fields empty and keeps the old ones. The store is in /data/store/results and the exports still to load are in /data/exports.

After `db.rename_fields(name_map)`, every record should have its value under the new name, keeping its type and field metadata, and the old name should be gone. Dataset metadata and other fields stay as they were. A key is a field name as `read()` shows it (dotted for sub-fields) or a nested record's name, which moves all of its sub-fields. Some v2 exports were already loaded, so a new name can already exist. Then the result is one field holding every record's value, typed as `create` would type both (whole numbers and floats give floats). If a record has values under both names, or a name was never in the store, raise ValueError and leave the store as it was.

Old names must keep working, also from a new `ParquetDB` on the same path and after a field is renamed again. Every export in /data/exports should load through `create` with all values under the new names, and `update` should accept old names too. Running the same rename again changes nothing.

There's no network, and the dependencies are installed in /opt/venv.
