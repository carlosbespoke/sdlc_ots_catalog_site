Long-running commands in shell-plugins cannot renew provisioned credentials through stable leases without restarting or changing the transport selected during provisioning. Implement renewal while preserving existing one-shot outputs and behavior when credentials are not refreshed.

The `github.com/1Password/shell-plugins/sdk` lease contract exposes `LeaseID`, `ProvisionCapability`, `ProvisionLease`, `RefreshInput`, `RefreshOutput`, `Provisioner.Refresh`, and `NewProvisioner`. Leases have stable identities. Static leases have no meaningful expiry and deterministically reject refresh. Renewable leases expose actual expiry through structured replacement effects and diagnostics.

Each provisioner must renew its original representation or refuse without mutating prior effects. AWS CLI reuses its selected profile without restoring consumed profile flags. STS reuses its provider path. ngrok preserves environment or YAML transport. GitHub and PyPI replace exactly their initial credential variables without changing unrelated environment entries or command arguments. CrateDB, Redis, and Vercel remain static because authentication is command-bound.

Failed provisioning creates no renewable lease. The RPC server retains only successful renewable leases. Refresh is atomic: failure preserves the previous lease for retry, while successful replacement retains its identity. RPC refresh matches provisioner and lease identities and routes to the originating implementation. Deprovision closes the addressed lease exactly once.

Schema projection, direct provisioner behavior, and RPC serialization must consistently advertise the selected default or usage-specific provisioner's capability. The `github.com/1Password/shell-plugins/sdk/rpc/server` exports `NewRPCServer(p)` returning `*RPCServer`. `github.com/1Password/shell-plugins/sdk/plugintest` exports `TestRenewableProvisioner(t, provisioner, cases)` and `RenewalCase` with fields `Provision`, `RefreshInput`, and `ExpectedRefresh`.

An AWS CLI lease created with a named profile keeps it across environment changes and remains retryable after failed refresh. Failed STS refresh through RPC exposes no partial replacement and preserves the prior lease for a later successful attempt. A file-backed ngrok lease refreshes its original temporary YAML path and becomes unavailable after deprovision. A GitHub usage override and default provisioner remain independently identifiable in serialized capability projection and refresh routing. Leases with equal expiry but different default and usage ProvisionerIDs remain distinct throughout schema projection and RPC routing.
