Give every Message a deterministic completion scope so deferred work runs exactly once at the true end of protocol activity. Completion ownership and outcomes must remain coherent across server dispatch, streaming, WebSockets, middleware, sessions, controllers, and outbound requests without changing established wire behavior.

Completion is an atomic, inspectable settlement: synchronous and asynchronous callbacks run once in reverse registration order, including callbacks added during settlement, while concurrent callers receive the same immutable result. Callback failures never stop settlement and appear as CompletionCallbackError values in occurrence order; cancellation of a completion caller does not leave settlement partial. Ownership transfers once, and any repeated transfer raises CompletionOwnershipError without invoking or moving callbacks. HTTP, ServerSentEventsResponse, and WebSocket settle only at their actual terminal protocol boundary, preserving transport, provider, handler, disconnect-code, and cancellation causes while avoiding duplicate sends or closes. ServerSentEventsResponse settles only after provider exhaustion, provider failure, send failure, or cancellation; provider failure remains its cause, and cancellation closes the active provider before settlement finishes. Dispatch, nested middleware, session persistence, normalized asynchronous generators, and controller lifetimes retain ownership and resources until delivery finishes, with cleanup completed and session persistence treated as part of settlement: it finishes before callbacks observe the outcome, any persistence failure becomes the completion cause, and saving occurs at most once. Redirects settle abandoned responses while one logical client request spans retries and redirects; timeout, exhaustion, middleware failure, and caller cancellation settle it once before propagating their terminal error and never create an extra attempt. Existing HTTP and SSE output, WebSocket state and close payloads, exception conversion, sessions, middleware, and redirect mutation, cookies, and history remain unchanged.

Nested middleware and an endpoint observe reverse callback order only after buffered response delivery succeeds. An SSE provider failure closes its generator before one result exposes both the provider cause and independent callback failures. A route exception retains its existing response while ownership transfers through unchanged status, headers, and body delivery. A controller accepting a WebSocket remains alive until peer disconnect and completion settle together exactly once. A redirected request that retries completes abandoned responses before its logical callback runs after final success.
