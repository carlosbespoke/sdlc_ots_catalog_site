regclient cannot reuse resource identity across manifest, blob, tag-list, and repository-list reads to detect changes without downloading or parsing content again. Implement one scheme-independent modified or not-modified contract while preserving ordinary read ownership and content behavior.

A nonempty `Validator.Match` succeeds only when populated identity fields are compatible; conflicting strong identities and empty validators never match. `tag.List.Validator`, `repo.RepoList.Validator`, `blob.BReader.Validator`, and `manifest.Manifest.Validator` expose reconciled response, descriptor, pagination, and scope identity without changing values or consuming streams. `scheme.WithConditional` applies a `Conditional` validator to existing scheme operations.

Remote validators become HTTP preconditions. A 304 returns `StateNotModified` without a fabricated typed value or body, including facade manifest reads. OCI-directory manifest and tag reads derive identity from current local content without fabricated HTTP metadata. A replaced local manifest returns the newly resolved typed manifest.

Clients created by `New` return `StateModified` with the current resource and reusable validator, or `StateNotModified` without a replacement resource. Modified blob bodies stay unread and caller-owned, and close exactly once under the existing reader contract. Unchanged responses retain no resource.

Remote tag pages keep existing append behavior and produce one complete-result validator. Conditional catalog reads preserve hostname scope and distinguish registry failures from unchanged responses. Unconditional behavior, options, pagination, formatting, manifest identity precedence, input validation, and resource-specific errors remain unchanged. Failures never report successful revalidation.
