The Terraform for our LaunchDarkly demo manager production stack in `/workspace/infra` has grown into one flat root module: everything is declared at the top level, the per-AZ resources are `count`-indexed by list position, and names, settings and tags are hard-coded all over the files. Split it into four local modules (network, compute, storage and observability) without touching the running infrastructure: against the current state, the plan has to come out as nothing but moves.

There is no AWS access from this machine. `terraform init` works offline from the local provider mirror, `terraform.tfstate` is a copy of the production state, and `scripts/ci-plan.sh` runs what CI runs: a `terraform plan -refresh=false` against the state followed by the guardrail policies in `policies/`.

## Detailed Constraints

**How CI judges the change.** CI takes the repository alone and plans it with `terraform plan -refresh=false` against its own copy of the production state. Local `terraform state` commands and edits to `terraform.tfstate` never reach it, so the whole migration has to be expressed in the configuration. That plan must:
- still manage every resource that is in the state today, and
- contain no create, update, replace, destroy or forget: only resources moving to new addresses.

The guardrail policies in `policies/` must pass on that plan, and `providers.tf` and everything in `policies/` stay exactly as they are, byte for byte.

**Layout.**
- The root module calls `module "network"`, `module "compute"`, `module "storage"` and `module "observability"`, with sources `./modules/network`, `./modules/compute`, `./modules/storage` and `./modules/observability` and one instance each, calls no other module and declares no resources of its own.
- Which module owns what (every instance of the resources described, wherever they are declared today):
  - network: the VPC, internet gateway, public, private and database subnets, NAT gateways and Elastic IPs, route tables, routes and route table associations, the S3 gateway endpoint with all of its route table associations, and the per-zone manifest, zone catalog and primary-private-subnet parameters;
  - compute: the builder IAM role, instance profile, managed attachment and runtime policy, the builder and load balancer security groups and their rules, the builder log group and launch template, the load balancer, target group and listener, the auto scaling group, the alarm topic and metric alarms, and the builder log-group parameter;
  - storage: the storage KMS key and alias, the state bucket and all of its settings, the state-lock DynamoDB table, every artifact bucket and all of their settings, every artifact event log group, capacity alarm, classification and settings parameter, the artifact and observability catalogs, the primary-artifact parameter, and the builder's artifact-access role policy;
  - observability: the VPC flow log, its CloudWatch log group, IAM role and inline policy, and every per-zone network-event log group and NAT-error alarm.
- Each of these modules declares the resources it owns itself and calls no other module.
- Modules get each other's IDs and ARNs through module outputs and variables. Never paste an ID, ARN, IP address or DNS name of an existing resource, or any part of one (such as an ARN suffix), into the `.tf` files or templates. The configuration reads files only through literal paths inside its own module (such as `"${path.module}/templates/..."`; in a child module a path starts with `${path.module}/`, because Terraform resolves any other relative path from the root directory, not from the module): no computed paths, no `terraform_remote_state` data sources, and never the state or a plan file.

**Keys.**
- Everything that exists once per availability zone today is a `for_each` resource keyed by the AZ name (for example `["us-east-1a"]`), including each instance of a list that also holds things that belong to no single availability zone (the S3 endpoint's associations with the private route tables; its association with the public route table is not per AZ).
- The primary-private-subnet parameter holds the private subnet ID from the zone with the lowest `failover_priority`, breaking ties by AZ name; if that zone is removed or priorities change, it falls back by the same rule. The map must remain nonempty.
- Everything that exists once per artifact store today is a `for_each` resource keyed by the artifact-store name (for example `["templates"]`), including each instance of a list that also holds things that belong to no single artifact store.
- The primary-artifact parameter holds the bucket name from the store with the lowest `priority`, breaking ties by artifact-store name; if that store is removed or priorities change, it falls back by the same rule. The map must remain nonempty.
- Don't use `count` anywhere. Other repeated resources use `for_each` with string keys that are not numbers (a name such as `["assets"]`, never `["0"]`).
- Each existing availability zone's entry in `availability_zones` is the only source of its values: changing an entry changes, for that availability zone alone, exactly the settings the entry provides, and changes nothing else.
- Adding an availability zone to `availability_zones` must plan only the creation of that availability zone's resources, each configured exactly like its counterparts in the existing availability zones apart from the availability zone itself and the values its entry in `availability_zones` gives it (same settings, names and tags), and removing one only the destruction of that availability zone's resources. Beyond that, the only change either may plan is an in-place update of the settings that collect something from every availability zone today (wherever a setting holds a part of every availability zone: their names, IDs, ARNs, subnets or CIDRs, say, in a list, a policy document or an environment value): each of them must take in, or drop, exactly that availability zone's part where it belongs, in the same form as today (today's parts keep their order, except inside an IAM policy document, where the order of statements, actions and resources means nothing to AWS; where a new part goes is up to you), and change nothing else. No other resource may be created, updated, replaced or destroyed.
- Each existing artifact store's entry in `artifact_stores` is the only source of its values: changing an entry changes, for that artifact store alone, exactly the settings the entry provides, and changes nothing else.
- Adding an artifact store to `artifact_stores` must plan only the creation of that artifact store's resources, each configured exactly like its counterparts in the existing artifact stores apart from the artifact store itself and the values its entry in `artifact_stores` gives it (same settings, names and tags), and removing one only the destruction of that artifact store's resources. Beyond that, the only change either may plan is an in-place update of the settings that collect something from every artifact store today (wherever a setting holds a part of every artifact store: their names, IDs, ARNs, subnets or CIDRs, say, in a list, a policy document or an environment value): each of them must take in, or drop, exactly that artifact store's part where it belongs, in the same form as today (today's parts keep their order, except inside an IAM policy document, where the order of statements, actions and resources means nothing to AWS; where a new part goes is up to you), and change nothing else. No other resource may be created, updated, replaced or destroyed.

**Root variables.** Declare these in the root module, each defaulting to today's value:
- `project` (`string`, `"lddemo"`): every whole-word occurrence of `lddemo` in a resource name, identifier or tag value today comes from it (whole word: not part of a longer run of letters and digits, so `lddemo-api`, `lddemo_key` and `/lddemo/` count, while a longer word that merely contains `lddemo` stays as it is), and so does every mention of those names elsewhere in the configuration (for example a resource name inside a policy); inside documents such as policies, container definitions and environment values, every whole-word occurrence of `lddemo` that stands for it comes from it too; the same whole-word rule also applies in free-text resource descriptions.
- `environment` (`string`, `"prod"`): every whole-word occurrence of `prod` in a resource name, identifier or tag value today, and the `APP_ENV` value and filesystem path written by the builder launch template's user data, comes from it (whole word: not part of a longer run of letters and digits, so `prod-api`, `prod_key` and `/prod/` count, while a longer word that merely contains `prod` stays as it is), and so does every mention of those names elsewhere in the configuration (for example a resource name inside a policy); inside documents such as policies, container definitions and environment values, every whole-word occurrence of `prod` that stands for it comes from it too; the same whole-word rule also applies in free-text resource descriptions.
- `vpc_cidr` (`string`, `"10.72.0.0/16"`): the VPC CIDR block and the operator SSH rule's source range; subnet CIDRs do not follow it.
- `availability_zones`: `map(object({ public_cidr = string, private_cidr = string, database_cidr = string, log_retention_days = number, nat_error_threshold = number, failover_priority = number, routing_class = string }))`, keyed by AZ name, defaulting to today's three AZs and their public, private and database subnet CIDRs, zone log retention, NAT-error threshold, failover priority and routing class. It is the only source of all of those per-zone values.
- `artifact_stores`: `map(object({ retention_days = number, classification = string, log_retention_days = number, warning_bytes = number, priority = number }))`, keyed by artifact-store name, defaulting to today's three stores and their retention periods, classifications, event-log retention periods, capacity-warning byte thresholds and priorities. It is the only source of all of those per-store values.
- `tags` (`map(string)`, `{ Owner = "solutions-engineering", CostCenter = "cc-2471", ManagedBy = "terraform" }`): the shared tags (`Owner`, `CostCenter` and `ManagedBy`) that tagged resources carry today. Wherever the configuration writes them out today, in any form, they come from this variable, so that a different map (other keys, other values) reaches every one of those places; a resource's other tags stay as they are, and resources that are untagged today stay untagged.
- `builder_ami_id` (`string`, `"ami-0009de7aaac3fdbb1"`): the builder launch template's AMI.
- `builder_instance_type` (`string`, `"t3.micro"`): the builder launch template's instance type.
- `builder_volume_size` (`number`, `24`): the builder launch template's root EBS volume size in GiB.
- `builder_min_size` (`number`, `1`): the builder auto scaling group's minimum size.
- `builder_max_size` (`number`, `2`): the builder auto scaling group's maximum size.
- `builder_desired_capacity` (`number`, `1`): the builder auto scaling group's desired capacity.
- `log_retention_days` (`number`, `30`): the retention period of the builder and VPC flow log groups; per-zone and per-artifact event-log retention comes from the corresponding map entry.
- `alarm_period` (`number`, `300`): the metric period of both builder metric alarms; per-zone and per-artifact alarm periods keep their current fixed values.
- `alarm_evaluation_periods` (`number`, `2`): the evaluation-period count of both builder metric alarms; per-zone and per-artifact alarms keep their current fixed count.
- `lb_idle_timeout` (`number`, `60`): the builder load balancer's idle timeout.
- `state_noncurrent_retention_days` (`number`, `90`): the state bucket lifecycle rule's noncurrent-version retention period.
- Changing `vpc_cidr`, `builder_ami_id`, `builder_instance_type`, `builder_volume_size`, `builder_min_size`, `builder_max_size`, `builder_desired_capacity`, `log_retention_days`, `alarm_period`, `alarm_evaluation_periods`, `lb_idle_timeout` and `state_noncurrent_retention_days` changes only what each one's line above says it controls: every other setting keeps today's value, including a setting that merely has the same value today.

**Root outputs.** Keep `vpc_id`, `builder_dns_name`, `builder_asg_name`, `state_bucket_name`, `state_lock_table_name` and `alarm_topic_arn` with their current values. Add `primary_private_subnet_parameter_name`: the `name` of `aws_ssm_parameter.primary_private_subnet`. Add `primary_artifact_parameter_name`: the `name` of `aws_ssm_parameter.primary_artifact`. `public_subnet_ids` becomes a map from the AZ name to the `id` of that availability zone's `aws_subnet.public`. `private_subnet_ids` becomes a map from the AZ name to the `id` of that availability zone's `aws_subnet.private`. `artifact_bucket_names` becomes a map from the artifact-store name to the `bucket` of that artifact store's `aws_s3_bucket.artifacts`. `database_subnet_ids` is a new output: a map from the AZ name to the `id` of that availability zone's `aws_subnet.database`. `zone_manifest_parameter_names` is a new output: a map from the AZ name to the `name` of that availability zone's `aws_ssm_parameter.zone_manifest`. `zone_event_log_group_names` is a new output: a map from the AZ name to the `name` of that availability zone's `aws_cloudwatch_log_group.zone_events`. `nat_error_alarm_names` is a new output: a map from the AZ name to the `alarm_name` of that availability zone's `aws_cloudwatch_metric_alarm.nat_errors`. `artifact_settings_parameter_names` is a new output: a map from the artifact-store name to the `name` of that artifact store's `aws_ssm_parameter.artifact_settings`. `artifact_event_log_group_names` is a new output: a map from the artifact-store name to the `name` of that artifact store's `aws_cloudwatch_log_group.artifact_events`. `artifact_capacity_alarm_names` is a new output: a map from the artifact-store name to the `alarm_name` of that artifact store's `aws_cloudwatch_metric_alarm.artifact_capacity`. Each output passes through outputs of the module that owns the resource (network for `vpc_id`, `public_subnet_ids`, `private_subnet_ids`, `database_subnet_ids`, `zone_manifest_parameter_names` and `primary_private_subnet_parameter_name`; compute for `builder_dns_name`, `builder_asg_name` and `alarm_topic_arn`; storage for `artifact_bucket_names`, `state_bucket_name`, `state_lock_table_name`, `artifact_settings_parameter_names`, `artifact_event_log_group_names`, `artifact_capacity_alarm_names` and `primary_artifact_parameter_name`; observability for `zone_event_log_group_names` and `nat_error_alarm_names`): the root output is a plain reference to an output of that module, and that module output is a plain reference to the resource. A plain reference is a reference such as `module.network.<output>` or `<resource type>.<name>.<attribute>`, a local that holds one, or a `for` expression that only re-keys one (`{ for k, v in <reference> : k => v.id }`) or iterates a plain reference and looks each key up in one (`{ for k, v in var.<map> : k => <reference>[k].id }`); no literals, function calls, conditionals or string templates anywhere along the way.

**Not allowed anywhere in the configuration:** `ignore_changes`, `prevent_destroy` and `replace_triggered_by`, `removed` and `import` blocks, provisioners, `external` data sources, backend or cloud blocks, provider blocks other than the one in `providers.tf`, override files and `.tf.json` files.
