The repository at `/workdir` is SQLFluff, a dialect-flexible SQL linter and auto-formatter
written in Python. Its lint rules are organised in rule bundles, each rule reporting violations
of one convention and often offering an automatic fix.

Fix all implementation drift from the documentation within SQLFluff's bundled rule catalog.
Everything in scope is SQLFluff's bundled rule catalog: every rule bundle under src/sqlfluff/rules/ except the layout bundle in src/sqlfluff/rules/layout/, the rule configuration defaults those bundles read from src/sqlfluff/core/default_config.cfg, and the documentation that describes them, which is the docstrings in those bundles (rendered as the rules reference) together with docs/source/reference/rules.rst.

Where the code and the documentation disagree about behavior, the documentation is the authority:
change the implementation so that it does what the documentation says, and do not edit or delete
documentation to make a disagreement go away. The documentation includes the docstrings and
the SQL examples in them. Behavioral comments inside the code are supporting evidence only; when
they conflict with the documentation, follow the documentation.

Keep the public API stable and keep every behavior that already matches its documentation
working exactly as it does now.
