Give registrars and the national dashboard read models that follow core's committed birth records. Extend the TypeScript workspace at `/app`: Elasticsearch search and workqueues, and Testland's `analytics.event_actions`, should reflect the committed actions rather than an action-confirmation response. The deliverable is a source change, not a report.

For records created, notified, and assigned through events, search and workqueue results and analytics actions must agree with committed record state. Once core accepts a confirmation, including an asynchronously accepted request, it appears in analytics; a confirmation without a core commit never creates an Accepted analytics row. Each committed change reaches both projections after an events instance dies immediately after commit, including when that instance cannot reach Elasticsearch or Testland. A surviving instance resumes delivery. Repeated delivery cannot duplicate analytics actions; delayed or older batches must not overwrite newer state. In particular, `/reindex` receives full-record batches that may include a numeric per-record `version`: a batch at version 1 must not undo a previously applied version 2 for that record, while replaying version 2 must not create duplicate actions. Elasticsearch document versions must likewise advance with committed action history (a created-then-notified record has a version of at least 2). Delivery may be asynchronous, but projections must converge within 30 seconds with healthy dependencies (or after dependencies recover), and a subsequent successfully projected marker action on another record must not leave an earlier committed change missing.

Online reindexing must preserve changes to previously streamed records and newly created records while writes continue. When it completes, the live index and analytics reflect those changes. Two overlapping runs may refuse one run, but cannot install a stale projection. Keep `/config/events`, `/reindex`, action-confirmation routes and events `/ping` available.

PostgreSQL and Elasticsearch are reachable at `postgres:5432` and `elasticsearch:9200`. The workspace uses `EVENTS_POSTGRES_URL`, `ANALYTICS_DATABASE_URL`, `ES_URL`, and `COUNTRY_CONFIG_URL`. From `/app`, build with `corepack pnpm --filter '@opencrvs/events...' run build` (the events service and the workspace packages it depends on, such as `@opencrvs/commons`) then `corepack pnpm --filter @opencrvs/toolkit run build` (Testland reads the shared event types from the toolkit build, not from commons directly) and `corepack pnpm --filter @opencrvs/testland run test:compilation`. Docker is unavailable inside the agent container.
