# Pinned API contracts during upgrades

Integrators need to keep the pricing and BOM contract they were built against while web and import workers roll forward independently. Extend the Django API at `/app/src/backend/InvenTree` to support pinned versions 561–564 using `X-InvenTree-API-Version: N`; unpinned requests retain version 564 behavior and the `X-InvenTree-API: 564` response header.

- A pin outside 561–564, or a nonnumeric pin, returns 400 or 406 and identifies the supported range.
- At 561, `/api/part/sale-price/` and `/api/part/internal-price/` handle price-break reads and writes directly, sharing stored data with `/api/pricing/sale-price/` and `/api/pricing/internal-price/`. `/api/part/<id>/pricing/` directly returns the same pricing record as `/api/pricing/part/<id>/`. Unpinned `/api/part/sale-price/` still returns a 308 redirect.
- At 561–563, `/api/bom/` detail and list responses compute `can_build`, `pricing_min_total`, and `pricing_max_total` without multiplying by `piece_count`; at 564 or unpinned, include it. Creating and patching a BOM under a pin preserve the actual `quantity` and `piece_count`.
- `/api/importer/session/` persists and reports the version selected when an import is created in its `api_version` field. Accepting its field mapping stages the CSV rows, including BOM `raw_amount` and `piece_count`, according to that stored version even if the acceptance request has no pin. A worker incapable of that version must leave the session for a capable worker; an unpinned import still stages on the default worker. If a pinned worker is SIGKILLed during staging, restarting a capable worker stages every row once, with no missing or duplicate rows, within 60 seconds of restart.

PostgreSQL and Redis are installed locally; start them with `sudo service postgresql start` and `sudo service redis-server start`. The database uses `INVENTREE_DB_*` environment variables. From `/app/src/backend/InvenTree`, `python manage.py migrate`, `python manage.py runserver`, and `Q_CLUSTER_NAME=InvenTree-api-563 python manage.py qcluster` run the API and a worker for pinned jobs; as shipped, that named-cluster worker stops with `KeyError: 'ALT_CLUSTERS'` because the worker configuration lacks the `ALT_CLUSTERS` entry django-q2 requires, so the configuration must provide it. Docker is unavailable inside the agent container.
