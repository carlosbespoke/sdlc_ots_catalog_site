# Shared RADIUS plan capacity

Subscribers with several devices need one plan limit across NASes and API instances. Extend FreeRADIUS authorization, accounting and background processing so capacity is shared rather than issued afresh to each connection.

- A `Simultaneous-Use` limit of one denies a second NAS/client while the first session is active, including authorizations arriving concurrently on different API processes; exactly one of two new concurrent requests is accepted. Reauthorizing the same NAS/client remains allowed without replenishing its reserved allowance.
- A successful authorization with no Accounting-Start holds its slot for the configurable `OPENWISP_RADIUS_SESSION_HOLD_SECONDS` (3 seconds here), then frees it; accounting Start retains the slot until Stop. Expired holds become available without a Celery run.
- For `Max-Daily-Session-Traffic` and time allowances, account for open and closed usage plus outstanding grants. Concurrent accepted replies' `CoovaChilli-Max-Total-Octets` and `Session-Timeout` grants together never exceed the remaining allowance, and a grant leaves room for the plan's other free `Simultaneous-Use` slots: a new authorization receives at most the remaining allowance divided by the free slots (all of it for the last one). At exhaustion return a Reject, not another grant.
- `Start`, `Interim-Update` and `Stop` accounting packets can repeat or arrive out of order. Recorded input/output octets and session time never fall, duplicate Stop does not reopen a session, and accounting GET retains these totals. When recorded traffic reaches a plan limit, an active session receives one acknowledged UDP Disconnect-Request within 30 seconds, sent by a Celery task that the accounting update queues (a worker runs, Celery beat does not); retry an unanswered request through Celery the same way, without duplicating a successful disconnect.
- Preserve authorization's `control:Auth-Type` Accept/Reject response, accounting POST's empty response body, and accounting GET's organization-scoped session list.

The repository is in `/app`. Run checks from `/app` with `python tests/manage.py check --settings=sd_settings`; the Django settings use PostgreSQL `sd` (`app:app` at localhost:5432), Redis at localhost:6379 and a 3-second hold. Start services with `sudo service postgresql start` and `sudo service redis-server start`. Celery's broker is Redis; API replicas and the worker share PostgreSQL. Docker is unavailable inside the agent container.
