Squidex stores asset events in PostgreSQL and file versions in MinIO. An API node can commit an asset before the final-key copy succeeds; a retry can then return the unreadable record as a duplicate. The worker processes events at least once, so a storage outage or restart can delay permanent deletion and repeat usage accounting. Make the asset record, its downloadable bytes, and reported storage usage converge without changing the existing asset HTTP contract.

For single-file `POST /api/apps/{app}/assets/` and `PUT /api/apps/{app}/assets/{id}/content/`, successful creation returns 201 and successful replacement returns 200; either must be downloadable with the submitted bytes at `GET /api/assets/{app}/{id}` through either API node. If MinIO is stopped during an upload for up to 20 seconds, the request must fail with 5xx without committing an asset; the same upload must succeed after recovery. If MinIO accepts the temporary upload but rejects the final-key write, creation and replacement must fail with 5xx without committing a new asset/version, preserve a replacement's previous bytes and fileVersion, and allow the identical request to succeed after storage recovers. Remove temporary objects left behind when a failed upload cannot clean up its staging key or its API process dies after staging but before committing, within 60 seconds after storage is available again. Ten simultaneous identical uploads divided between two API processes must all return 201 with one shared asset ID and one listed asset with that hash; exactly nine responses identify the duplicate using `_meta.isDuplicate` set to the string `"true"`, while the first creation has no `isDuplicate` field. Preserve `duplicate=true` creating a separate asset (201) even for identical bytes, the metadata route `GET /api/apps/{app}/assets/{id}/` (200), asset DTO fields including `id`, `fileHash`, `fileVersion` (initially 0), and the download route (200).

`DELETE /api/apps/{app}/assets/{id}/?permanent=true` must return 204 even if MinIO is unavailable; after storage recovers, all versions must disappear from the bucket within 15 seconds, with the first worker retry within 10 seconds of a failure. If the worker is killed while applying asset events blocked on either its event-consumer checkpoint row or a storage-usage counter row and restarted, the storage-usage counter backing `GET /api/apps/{app}/usages/storage/today/` must count each live file version's bytes exactly once and permanently deleted assets must leave no files. For one asset, upload accounts for its byte length, replacement adds the new version's byte length to the previous version's length, and permanent deletion clears both from usage. Tus, bulk uploads, thumbnails, backups and the external S3 client are outside this change.

The repository is at `/app` (`backend/src/` contains the service). Run builds there with `dotnet build backend/src/Squidex/Squidex.csproj -p:NuGetAudit=false`. PostgreSQL and MinIO are installed locally; start PostgreSQL with `sudo service postgresql start` when working interactively. The deployment uses `STORE__TYPE=Sql`, `EVENTSTORE__TYPE=Sql`, `MESSAGING__TYPE=Sql`, `ASSETSTORE__TYPE=AmazonS3`, path-style MinIO access, two API processes (`CLUSTERING__WORKER=false`) and one worker (`CLUSTERING__WORKER=true`). Docker is unavailable inside the container.
