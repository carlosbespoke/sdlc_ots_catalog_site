# Shared S3 tile rendering

## Goal
Enable independent MapProxy nodes and `mapproxy-seed` to coordinate rendering through their shared S3 tile cache, so a popular expiry does not overwhelm the upstream WMS.

## Requirements
1. A requested tile is returned as a PNG and persisted in S3. Twenty simultaneous requests for one tile of a 2×2 metatile across three processes should make exactly one upstream WMS request; seeding that metatile concurrently with serving it should also render it only once.
2. A render lease lasts 2 seconds. An active render taking longer than the lease duration must still render only once when seed and serving requests overlap. If its owner stops or stalls, another process can render after expiry; an older render completing after the replacement must not overwrite the newer S3 image. Separate nodes have private local lock directories, not a shared filesystem.
3. A source update announced by `refresh_before` or a seed/cleanup refresh reaches every node within `max_staleness` (5 seconds). An outdated tile may be served stale only while another process is rendering its replacement, and only within 5 seconds of the refresh starting (not of when a node notices it); otherwise the request renders the new tile or waits for it, as for a missing tile. A refresh begun by seeding or cleanup invalidates cached data across nodes even in areas outside that job's coverage.

## Keep compatible
The existing `/tms/1.0.0/<layer>/<grid>/<z>/<x>/<y>.png` route still serves PNG tiles; file caches still render once and return cached tiles. S3 caches without shared coordination keep their current behavior.

## Environment
Work in `/app`. Configure shared S3 coordination under `globals.cache.s3` with `coordination_url` (a Redis URL), `lease_seconds` and `max_staleness`; local Redis runs on `127.0.0.1:6379` (`sudo service redis-server start`). An S3-compatible emulator is available as `moto_server -H 127.0.0.1 -p 5000` with bucket credentials `testing`/`testing`, region `us-east-1`; WMS is an HTTP source. Run MapProxy via `mapproxy.wsgiapp.make_wsgi_app(config)` and the seeder via `mapproxy-seed -f mapproxy.yaml -s seed.yaml --seed demo` from `/app`. Docker is not available inside the agent container.
