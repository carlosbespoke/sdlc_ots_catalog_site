A stopped Dagster run worker can leave a global op-pool slot occupied forever; a paused worker can resume after its slot has been freed and execute alongside its replacement. Make PostgreSQL-backed op-pool slots expiring, fenced leases across run workers, the daemon and GraphQL.

- A claimed slot has an owner (`runId`, `stepKey`) and a visible expiry (`leaseExpiresAt`, Unix seconds, never more than 45 seconds after the last renewal) in `concurrencyKeyInfo.claimedSlots`. Renew it while the step runs; claims across processes never exceed the configured pool limit, including simultaneous claims for the last slot. Waiting steps receive freed slots in priority order.
- A holder that stops renewing gives up its slot within 45 seconds without requiring `run_monitoring.free_slots_after_run_end_seconds`, even when both the worker and its code server die. The owning run becomes FAILURE within the same 45 seconds, and a waiting step can then proceed. Keep this working when run monitoring is disabled.
- If a paused worker loses a lease, it must not start another pool step or report the interrupted step successful; after resuming it records step failure and ends the run FAILURE within 30 seconds. A lease can be lost while the step's code is still running, so the worker must confirm it still holds the lease when it records the step's outcome, not only when it claims or renews the slot. The same rule applies after `freeConcurrencySlots(runId, stepKey)` manually revokes a held slot; that mutation releases the slot within 5 seconds.
- Pre-existing claimed rows without lease metadata remain normally releasable by their run and are reclaimed after one lease period (15 seconds) when abandoned. Preserve existing pool limits, claimed-slot `runId`/`stepKey`, pending-step counts and the free-slots mutation; a released or reclaimed slot's `concurrency_slots` row has `run_id` and `step_key` cleared, as today.

Work in `/app`; PostgreSQL stores instance state. The canonical check runs from `/app` with `python -m pytest python_modules/dagster/dagster_tests/storage_tests/test_event_log.py -q`. Start PostgreSQL with `sudo service postgresql start` if needed; the local database role/password is `postgres`/`postgres`.
