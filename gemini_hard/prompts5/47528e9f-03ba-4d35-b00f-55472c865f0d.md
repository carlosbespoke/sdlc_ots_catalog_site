Add operation-scoped runtime readiness reports. Distinguish create-cluster and load-image. An unavailable explicit backend yields one unavailable, unready attempt, no selection, a blocked report and error findings. Findings include code, backend, operation, summary, severity and command evidence. Docker/Podman unavailability shares a code but retains different evidence. Findings follow backend-attempt order and remain attached to their backend. Repeated identical responses produce equal reports; changed availability changes the report. Evidence omits environment secrets.

Automatic checks retain Docker, nerdctl, then Podman attempts when none is ready. Explicit unavailable Podman never falls back. KIND_EXPERIMENTAL_PROVIDER maps nerdctl, finch and nerdctl.lima to one nerdctl-family attempt; create commands warn once with the supplied alias or unknown value. Provider checks retain explicit Podman selection.

Recognized Docker/nerdctl clients with failing daemon information are available but blocked. nerdctl takes precedence over Finch; Finch fallback retains its executable identity in evidence and JSON. Malformed Podman versions and version 1.7 block create checks; supported Podman create checks probe info and networks. Docker duplicate networks yield an error with code network-conflict. Docker rootless/devicemapper warn without blocking; nerdctl rootless warns and nondefault namespaces block. Rootless Podman load checks warn about volumes; Podman 1.9 load checks block.

Inspection avoids runtime mutations. Validate all load references before image inspection: invalid or mixed requests block image saving, copying and importing. Unavailable-runtime create gates block provisioning. Library, provider and CLI blocking decisions agree.

`kind runtime check --operation create-cluster|load-image --output human|json` prints reports even when blocked and returns an error when blocked. Human create-cluster output names attempted backends and the operation; JSON preserves library attempts/findings.
