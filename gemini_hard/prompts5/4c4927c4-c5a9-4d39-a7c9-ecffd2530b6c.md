# Coherent multi-tier ISR cache

We want to run the multi-tier ISR cache across independent server instances with bounded staleness and no torn page reads. The repository is at `/app`; the existing cache override, cache handler, SQS queue and revalidation adapter are the integration points.

## What we need

- A successfully stored page has a monotonically increasing revision; the first committed revision is 1 (0 means no committed page). Separate instances reading a page converge on the newest committed revision within `OPEN_NEXT_LOCAL_CACHE_TTL_MS` (set to 2000 milliseconds in the workload); a client polling instances round-robin never sees a revision decrease. Return the revision in `x-open-next-cache-version` for multi-tier page reads.
- A regeneration based on an earlier revision cannot replace a later committed regeneration, even if its S3 write finishes last. If a writer dies between its S3 data write and DynamoDB metadata write, reads continue to return the previously committed content and revision, never a mixture of versions.
- The cache handler preserves the revision it read when writing a regenerated page. Background revalidations retain their originating base revision through SQS and the revalidation HEAD request, in `x-open-next-base-version`.

## Keep working

- The plain `s3` and `s3-lite` overrides still overwrite and retrieve cache and fetch entries by key. Ordinary pages still round-trip through the cache handler; SQS revalidations still preserve their URL and host fields.

## Setup

`/opt/sd-workload.mjs` runs the repository cache and queue modules against LocalStack S3, DynamoDB and SQS; from `/app`, build with `pnpm --filter @opennextjs/aws build && pnpm --filter @opennextjs/aws exec esbuild /opt/sd-workload.mjs --bundle --platform=node --format=esm --packages=external --outfile=/app/packages/open-next/.sd-workload.mjs && cp /opt/sd-revalidate-config.mjs /app/packages/open-next/dist/core/open-next.config.mjs && pnpm --filter @opennextjs/aws exec esbuild /app/packages/open-next/dist/adapters/revalidate.js --bundle --platform=node --format=esm --packages=external --outfile=/app/packages/open-next/.sd-revalidate.mjs`; run with `node /app/packages/open-next/.sd-workload.mjs`, exposing `/entry`, `/page`, `/enqueue` and `/decode`. The revalidation adapter is available via `node /opt/sd-revalidate-endpoint.mjs` using `/opt/prerender-manifest.json`. AWS connection details come from `AWS_ENDPOINT_URL`, `CACHE_BUCKET_NAME`, `CACHE_DYNAMO_TABLE`, `REVALIDATION_QUEUE_URL` and the usual AWS credentials. Docker is unavailable inside the solver container; LocalStack runs as a sidecar. Your deliverable is the updated TypeScript source in `/app/packages/open-next/src`.
