# Reduce sympy workload overhead

The repository at `/app` is the source tree of `sympy`. The scripts in `/app/perf_workloads/` exercise parts of the library that currently do more work than necessary:

- `perf_workloads/workload_1.py`
- `perf_workloads/workload_2.py`
- `perf_workloads/workload_3.py`
- `perf_workloads/workload_4.py`

Make the code these workloads use materially faster. Find the unnecessary work and remove it while preserving the package's existing behaviour.

Python imports `sympy` from `/home/agent/site`. After changing the source, rebuild and reinstall it there, then run a workload:

```sh
rebuild-package
python /app/perf_workloads/workload_1.py
```

## Requirements

- Preserve the behaviour and public API of `sympy`, including results, raised exceptions, warnings, and which inputs are accepted or rejected.
- The hidden behaviour checks do not compare a few edge inputs, and behaviour on them is not graded: for `inv_mod`, moduli that are not prime, not integers or smaller than 2, matrices with non-integer entries, and the class of the returned matrix for immutable or sparse inputs; for `inv`, matrices with floating-point entries or non-commutative symbols, and the written arrangement of inverse entries that are not rational numbers (their values are still compared); for `charpoly` of a matrix, empty 0x0 matrices, matrices mixing floating-point numbers with symbols, the written form of coefficients when entries contain functions such as `sin`, `cos` or `exp` of symbols, and a custom `simplify` function combined with non-rational entries; and for `DomainMatrix.charpoly`, matrices over the raw expression domain (`EXRAW`).
- Keep the existing test suite passing. Run repository tests against the installed copy, for example `python -m pytest /home/agent/site/sympy/<path to a test file>`.
- Improve the general code paths the workloads exercise. Hidden checks run the same operations on different inputs, sizes and values, and check every result; do not special-case the visible scripts or their literal inputs.
- Do not modify or disable tests, benchmarks or the workload scripts. The verifier restores its own copies.
- Change only package source under `sympy/`; new modules inside the package are allowed. Keep build configuration, dependencies and all other files unchanged. Markdown notes are allowed outside `sympy/`.
- Do not add code that inspects the call stack, environment variables, the process, files, the network, timers, threads, subprocesses or CPU scheduling, and do not change behaviour according to how the code is being run or measured. This is checked mechanically on every changed source file: it may not add uses of introspection and tracing (such as `inspect`, `traceback`, `sys._getframe`), garbage collection (`gc`), dynamic code (`eval`, `exec`, `compile`, `globals`, `vars`, `__import__`, `builtins`), serialization (`pickle`, `marshal`, `shelve`), import machinery (`importlib`, `runpy`), exit hooks (`atexit`), files and I/O (`open`, `io`, `os.path`, `pathlib`, `shutil`, `tempfile`), the network, timers (`time`, `timeit`), threads and processes (`threading`, `multiprocessing`, `subprocess`, `concurrent`, `asyncio`, `os.fork`) or CPU affinity (`os.sched_setaffinity`), including through `getattr` on `os`, `sys` or `builtins`, or by using those modules as values (for example by assigning one to another name). Using one of these more times than the original file already does also counts.
- Each workload is timed on one CPU core; CPU time used beyond one core while a workload runs is added to its measured time.
- Work offline. The toolchain, dependencies and build cache are already present.

## Grading

Correctness is a hard gate. The repository tests that cover the optimized code must pass as they do on the untouched baseline, and hidden differential checks compare results with the baseline across many inputs; any difference receives no credit.

Each of the 4 workloads is timed through a hidden variant with fresh inputs, on the untouched baseline, on your version, and on a private reference, with ten fresh-process launches each on the same machine. A workload scores your speedup over the baseline divided by the reference's speedup, capped at 1. It scores 0 unless your timings are faster than the baseline's under an exact one-sided Mann-Whitney test at an alpha of 0.05. The result is 1 only when correctness passes and the harmonic mean of the 4 workload scores is at least 0.95; otherwise 0. One workload at 0 makes the harmonic mean 0. If the reference itself is not measurably faster than the baseline in a run, the evidence is discarded and the measurement is repeated once.
