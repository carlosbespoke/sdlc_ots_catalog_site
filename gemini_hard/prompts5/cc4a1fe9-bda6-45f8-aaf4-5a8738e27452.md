# Goal
A request that started before support deactivated a key can write its old session back after an administrator's change. Fix Redis-backed Gateway API keys so admin changes remain authoritative across two gateways, without losing request quota accounting.

# Requirements
1. `POST /tyk/keys/create`, `PUT /tyk/keys/{key}`, `GET /tyk/keys/{key}` and `DELETE /tyk/keys/{key}` continue to manage keys with `access_rights`, `is_inactive`, `quota_max`, `quota_remaining` and `quota_renewal_rate`. PUT completes only after the updated session is durable and its cache invalidation has been published. Expose the persistent key version as the numeric `key_version` field in `GET /tyk/keys/{key}` (including newly created keys). Concurrent PUTs to one key through either gateway all succeed, and each increments the stored version by exactly one, atomically across gateways; a session without a version is version zero.
2. A request already admitted on another gateway cannot restore a previous `is_inactive`, `access_rights` or `quota_max` after PUT completes, nor revive a deleted key. Requests admitted before the change remain counted in the current quota. Concurrent requests through both gateways do not lose quota usage: `GET /tyk/keys/{key}` reports `quota_remaining` as the current `quota_max` minus admitted usage (clamped at zero).
3. Both gateways reject an inactive key and a removed API right with HTTP 403 within two seconds of the PUT. If a gateway loses its Redis notification connection for 20 seconds, it must not authorize from a cached key older than two seconds during the cut; after recovery it rejects a changed key within two seconds, even if it missed the notification.

# Keep compatible
Keys stored without a version can still authenticate, be updated and be deleted. Existing key creation and the `Authorization` proxy header continue to work.

# Environment
The repository is at `/app`. Two gateway processes use one Redis on localhost:6379; start it with `sudo service redis-server start`. API definitions may be file-based. Build the gateway from `/app` with `go build -o /tmp/tyk .`, and start it with `--conf=<configuration file>`. Docker is unavailable inside the solver container.
