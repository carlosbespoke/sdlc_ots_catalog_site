# Reduce sklearn workload overhead

The repository at `/app` is the source tree of `sklearn`. The scripts in `/app/perf_workloads/` exercise parts of the library that currently do more work than necessary:

- `perf_workloads/workload_1.py`
- `perf_workloads/workload_2.py`
- `perf_workloads/workload_3.py`
- `perf_workloads/workload_4.py`
- `perf_workloads/workload_5.py`

Make the code these workloads use materially faster. Find the unnecessary work and remove it while preserving the package's existing behaviour.

Python imports `sklearn` from `/home/agent/site`. After changing the source, rebuild and reinstall it there, then run a workload:

```sh
rebuild-package

```

## Requirements

- Preserve the behaviour and public API of `sklearn`, including results, raised exceptions, warnings, and which inputs are accepted or rejected.
- The hidden behaviour checks do not compare a few edge inputs, and behaviour on them is not graded: histogram gradient boosting features that have no usable values (every value missing, or every non-missing row with zero weight), the internal-node values stored in the fitted trees of gradient boosting classifiers (predictions, probabilities, scores and leaf values are compared), the memory layout (C or Fortran order) of encoder output arrays, and cross-validation splitters that yield boolean masks or negative indices instead of arrays of non-negative indices.
- Keep the existing test suite passing. Run repository tests against the installed copy, for example `python -m pytest /home/agent/site/sklearn/<path to a test file>`.
- Improve the general code paths the workloads exercise. Hidden checks run the same operations on different inputs, sizes and values, and check every result; do not special-case the visible scripts or their literal inputs.
- Do not modify or disable tests, benchmarks or the workload scripts. The verifier restores its own copies.
- Change only package source under `sklearn/`; new modules inside the package are allowed. Keep build configuration, dependencies and all other files unchanged. Markdown notes are allowed.
- Do not add code that inspects the call stack, environment variables, the process, files, the network, timers, threads, subprocesses or CPU scheduling, and do not change behaviour according to how the code is being run or measured. This is checked mechanically on every changed source file: it may not add uses of introspection and tracing (such as `inspect`, `traceback`, `sys._getframe`), garbage collection (`gc`), dynamic code (`eval`, `exec`, `compile`, `globals`, `vars`, `__import__`, `builtins`), serialization (`pickle`, `marshal`, `shelve`), import machinery (`importlib`, `runpy`), exit hooks (`atexit`), files and I/O (`open`, `io`, `os.path`, `pathlib`, `shutil`, `tempfile`), the network, timers (`time`, `timeit`), threads and processes (`threading`, `multiprocessing`, `subprocess`, `concurrent`, `asyncio`, `os.fork`) or CPU affinity (`os.sched_setaffinity`), including through `getattr` on `os`, `sys` or `builtins`. Using one of these more times than the original file already does also counts.
- Each workload is timed on one CPU core; CPU time used beyond one core while a workload runs is added to its measured time.
- Work offline. The toolchain, dependencies and build cache are already present.

## Grading

Correctness is a hard gate. The repository tests that cover the optimized code must pass as they do on the untouched baseline, and hidden differential checks compare results with the baseline across many inputs; any difference receives no credit.

Each of the 5 workloads is timed through a hidden variant with fresh inputs, on the untouched baseline, on your version, and on a private reference, with ten fresh-process launches each on the same machine. A workload scores your speedup over the baseline divided by the reference's speedup, capped at 1. It scores 0 unless your timings are faster than the baseline's under an exact one-sided Mann-Whitney test at an alpha of 0.05. The result is 1 only when correctness passes and the harmonic mean of the 5 workload scores is at least 0.9; otherwise 0. One workload at 0 makes the harmonic mean 0. If the reference itself is not measurably faster than the baseline in a run, the evidence is discarded and the measurement is repeated once.
