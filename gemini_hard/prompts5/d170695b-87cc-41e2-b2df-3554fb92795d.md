Harbor persists scan and replication tasks in PostgreSQL but keeps job state in Redis. After Redis loses state, or a jobservice worker dies mid-job, tasks can remain Pending or Running indefinitely. Restore agreement between these services for `IMAGE_SCAN` and `REPLICATION` without altering unrelated job types or existing task, execution, and scan-report API fields/status values.

Provide an authenticated batch job-state query in jobservice at `POST /api/v1/jobs/states`: accept JSON `{"ids":["job-id",...]}` and respond with HTTP 200 and a JSON object mapping each requested ID to exactly one of `unknown` (no job state), `queued` (pending job), `running-on-live-worker`, `running-on-dead-worker`, or `final` (completed job), using worker-pool liveness to distinguish running jobs. Within 60 seconds of a worker pool's death, re-queue the in-progress jobs it held, of every job type: an IMAGE_SCAN or REPLICATION job that had not started yet is re-queued like any other, while one that had already started must not contact its scanner or registry a second time. In core, reconcile non-final tasks against jobservice across multiple core instances: within two minutes of loss each task must either complete after safe recovery or become Error, and its execution and scan report must reflect that final state so an artifact can be scanned again. A Redis flush affecting 20 pending or running scans must not leave any stuck tasks: when their jobs are irretrievably lost, both the task and its execution must reach the existing `Error` status (not remain `Pending` or `Running`). Do not resubmit a lost task more than once or run two copies concurrently; in particular, losing an already-started scan must not send a second request to its scanner. After a lost scan is finalized, a new scan request for the same artifact must be accepted (HTTP 202) and retain a single report record for that artifact/scanner. Do not fail or re-run healthy jobs simply because they have run for three minutes; their task and execution should remain `Running` while the worker is alive. A killed worker running a scan or replication job must also converge within two minutes, with lost work marked `Error` in both task and execution if it cannot be safely recovered. The repository is at `/app`. `/usr/local/bin/reproduce-loss` starts local services, seeds twenty stranded scan tasks, flushes jobservice Redis, and prints their task/execution states after 100 seconds; it can be run again to verify recovery. Build and test offline from `/app/src` using `go test ./pkg/task ./pkg/scan/vulnerability ./jobservice/api ./jobservice/core ./jobservice/mgt ./jobservice/worker/cworker ./controller/scan ./controller/replication` with local PostgreSQL and Redis running and Harbor's normal test environment variables configured.
