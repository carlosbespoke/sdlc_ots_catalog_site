Webhook flows can be run twice when a worker loses its BullMQ lock and later resumes, and an older attempt can overwrite a newer run's status or outputs. Implement leased, fenced `EXECUTE_FLOW` execution across the API, worker and engine. Keep the existing `poll`, `extendLock`, `completeJob`, `/api/v1/engine/{run-progress,step-progress,run-logs,flow-response}` and `/api/v1/flow-runs` interfaces usable for healthy clients; a lease must have an increasing attempt identity per run, and stale progress, logs, responses and completion must be refused (HTTP callbacks return 409). A terminal run's status and outputs remain final.

With `AP_WORKER_JOB_LEASE_SECONDS=10`, a healthy webhook run taking 30 seconds must complete once, preserving both HTTP step outputs. Extend at least every third of the lease; if extending fails or the lease is lost, stop the engine within one lease period and do not complete the old job. With two workers, a worker paused beyond the lease or killed mid-run must have its job reclaimed within 35 seconds, finish on another worker, and never make further HTTP side effects or accepted writes after resuming. After Redis is unavailable for 20 seconds, the run must succeed within 45 seconds of recovery, without recording outputs from different attempts. `GET /api/v1/flow-runs/:id` and the list route retain their existing response shapes, statuses and step outputs.

The source is at `/app` (TypeScript/Bun workspace). PostgreSQL and Redis are installed locally; `agent` can start them with `sudo service postgresql start` and `sudo service redis-server start`. PostgreSQL's `postgres` user has password `postgres` and Redis listens on 6379. Use `bun run turbo run build --filter=api... --filter=worker... --concurrency=4 --env-mode=loose` from `/app` to rebuild offline. No Docker socket is available in the container. Scope excludes pause/resume, polling, subflows, agent jobs and EE concurrency pools.
