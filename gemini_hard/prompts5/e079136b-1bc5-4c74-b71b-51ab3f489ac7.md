# Station presence across replicas

The team needs one station connection owner across OCPP instances and ordered availability for roaming partners.

## Background
Connections use Redis leases and RabbitMQ commands. OCPI Locations serves roaming partners.

## Proposal
Work in `/app`; deliver TypeScript changes and any migrations there.

## Requirements
- A connected station has `ChargingStations.isOnline` true and, when its last known connector status is Available, partner EVSE status `AVAILABLE`. A command issued on another OCPP instance reaches that socket once and returns its result. A normal disconnect makes the station offline and pushes `UNKNOWN`.
- After lease expiry and reconnection elsewhere, the former owner cannot renew or remove the new slot, mark the station offline, remove its routing, answer through the old socket, or return a stale “not connected” error. A third connection is refused while the new owner holds the slot. Commands from a third instance reach the current socket once even while the old owner remains paused and bound to RabbitMQ.
- After an owner is killed and the station reconnects, partners see `UNKNOWN` between online states and finish online. Across two OCPI instances, a delayed older presence push cannot overwrite a newer one at the partner. Changes during OCPI downtime reach the partner within 45 seconds of restart; a waking former owner sends no presence change.

## Compatibility
Honor unversioned slots written by existing OCPP instances until their TTL expires. Preserve the `ocpp2.0.1` WebSocket upgrade, remote `POST /ocpp/2.0.1/configuration/reset`, and presence pushes keep using the existing OCPI Locations EVSE `PATCH` path.

## Environment
The workspace builds offline with `pnpm run build` from `/app`; Docker is unavailable. Start local PostgreSQL, Redis and RabbitMQ with `sudo service postgresql start`, `sudo service redis-server start`, and `sudo service rabbitmq-server start`; Hasura is installed. Database `citrine` uses `app:app`. Run each server with `node dist/index.js` from its app directory. For `apps/ocpp-server` use `CITRINEOS_DATABASE_USERNAME=app`, `CITRINEOS_DATABASE_PASSWORD=app`, `CITRINEOS_CACHE_TYPE=redis`, `CITRINEOS_CACHE_URL=redis://localhost:6379` and distinct `CITRINEOS_MESSAGEBROKER_AMQP_INSTANCEIDENTIFIER` values. For `apps/ocpi-server` use `APP_ENV=docker`, `DB_HOST=localhost`, `DB_NAME=citrine`, `DB_USER=app`, `DB_PASS=app`, `GRAPHQL_ENDPOINT=http://localhost:8090/v1/graphql`, `AMQP_URL=amqp://guest:guest@localhost:5672`. OCPI replicas accept `OCPI_PORT` for their HTTP port (default `8085`) so they can run together.
