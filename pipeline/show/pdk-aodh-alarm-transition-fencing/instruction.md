# Fence and deliver Prometheus alarm transitions

Aodh's Prometheus threshold alarms currently commit state independently of action delivery. Make their state changes safe across evaluator handover and concurrent API updates, and make their REST webhooks durable and ordered. Work in `/app`; the deliverable is a patch to this repository. PostgreSQL, Redis coordination, and RabbitMQ are available. The evaluator, API, and two notifier instances must work against the same database.

Each committed state transition, whether caused by evaluation or `PUT /v2/alarms/{id}/state`, must have a gap-free per-alarm `sequence` (starting at 1) exposed in the history API; its history `detail` JSON must keep the new state as `state` and record the previous state as `previous`, which must equal the last committed state. Concurrent state PUTs, including through different API processes, must all succeed and commit one after another. A delayed evaluator must not commit a result computed before another evaluator evaluated that alarm, even if that evaluation left the state unchanged; nor may it commit a result predating an API state change. An evaluator paused through a Redis/tooz partition handover must not overwrite the new owner's result or send its obsolete action.

For every committed transition with configured actions, deliver its REST webhook to each configured REST action, in per-alarm sequence order across notifier instances and restarts. Include a stable `X-Aodh-Transition-Id` HTTP header matching the transition's history event ID; retries after an uncertain response must reuse the ID. Evaluation and `PUT /v2/alarms/{id}/state` must keep succeeding and committing transitions while RabbitMQ is down. Each webhook must reach its receiver within 45 seconds of its commit, or of recovery from a 20-second RabbitMQ or webhook outage. A notifier killed during delivery must leave the transition recoverable by another instance. Existing webhook body fields and legacy RabbitMQ alarm notifications without a sequence must continue to work. Transitions, their history, and pending actions must commit atomically; receiver-side deduplication by transition ID is allowed for uncertain POST responses.

The repository's existing test suites and the service command for this task run from `/app`; the service executables are `/app/.venv/bin/aodh-api`, `/app/.venv/bin/aodh-evaluator`, and `/app/.venv/bin/aodh-notifier`; all of a service's work must stay in its process tree, since killing a service also kills any detached process it left. Out of scope are event, composite, Gnocchi, Heat, and Zaqar alarm integrations.
