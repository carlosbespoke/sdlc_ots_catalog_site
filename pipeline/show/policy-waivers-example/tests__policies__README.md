# Platform policy pack

OPA/Rego rules that conftest evaluates on the JSON form of a Terraform plan (`terraform show -json`). Each rule is its own package (`rules.<id>`), so CI evaluates every package: `conftest test --all-namespaces --policy policies <plan.json>`. A rule reads the planned values of the resources the plan keeps, updates or creates (`resource_changes[].change.after`); a value that is only known after apply never satisfies a rule. `lib/tf.rego` holds the helpers the rules share (how resources, KMS key references, bucket settings, queue policies, role permissions and security group rules are found).

Conventions used by the rules:

- *This stack's KMS key* is a customer managed key (`aws_kms_key`) managed in the same plan, named by its ARN, its key ID, or the name or ARN of one of its aliases (`aws_kms_alias`), except where a rule asks for the key's ARN.
- *Of this stack* means managed in the same plan. Bucket settings resources (`aws_s3_bucket_*`) belong to the bucket named in their `bucket` argument, queue policies to the queue whose URL is their `queue_url`, a role's permissions are its inline policies plus the policies attached to it.
- Policy documents are read as JSON; one that is not known when the plan is made fails `POL-001`.

| Rule | File | Requirement |
|---|---|---|
| APIGW-001 | `compute/apigw_001.rego` | **API stages are traced.** Every API Gateway REST API stage sets `xray_tracing_enabled` true. |
| EC2-001 | `compute/ec2_001.rego` | **Launch templates require IMDSv2.** Every launch template sets `metadata_options` with `http_tokens` `required` and, when set, an `http_put_response_hop_limit` of at most `2`. |
| EC2-002 | `compute/ec2_002.rego` | **Instances require IMDSv2.** Every instance sets `metadata_options` with `http_tokens` `required`. |
| EC2-003 | `compute/ec2_003.rego` | **Launch template volumes are encrypted with the stack key.** Every EBS volume a launch template defines (`block_device_mappings` `ebs`) sets `encrypted` true and `kms_key_id` to the ARN of this stack's KMS key. |
| ECS-001 | `compute/ecs_001.rego` | **Container Insights is on.** Every ECS cluster has a `setting` `containerInsights` with value `enabled` or `enhanced`. |
| LMB-001 | `compute/lmb_001.rego` | **Functions use active tracing.** Every Lambda function sets `tracing_config` with `mode` `Active`. |
| LMB-002 | `compute/lmb_002.rego` | **Function environments are encrypted with the stack key.** A Lambda function that has environment variables sets `kms_key_arn` to the ARN of this stack's KMS key. |
| EXC-001 | `custom/exc_001.rego` | **Exceptions register entries are valid.** Every entry of the exceptions register (`exceptions/register.json`, loaded by CI with `--data exceptions`) is valid as `EXCEPTIONS.md` defines it: its `id`, `rule`, `address`, `owner`, `ticket`, `expires` and `reason` meet the rules there, and no other entry names the same rule and address. An invalid entry waives nothing. |
| DDB-001 | `data/ddb_001.rego` | **Tables keep point-in-time backups.** Every DynamoDB table has `point_in_time_recovery` enabled. |
| DDB-002 | `data/ddb_002.rego` | **Tables are encrypted with the stack key.** Every DynamoDB table sets `server_side_encryption` with `enabled` true and `kms_key_arn` the ARN of this stack's KMS key. |
| DDB-003 | `data/ddb_003.rego` | **Tables are protected from deletion.** Every DynamoDB table sets `deletion_protection_enabled` true. |
| RDS-001 | `data/rds_001.rego` | **Databases keep automated backups.** Every DB instance (other than a read replica) and every DB cluster keeps automated backups for at least `7` days (`backup_retention_period`). |
| RDS-002 | `data/rds_002.rego` | **Databases are protected from deletion.** Every DB instance and DB cluster sets `deletion_protection` true. |
| RDS-003 | `data/rds_003.rego` | **Deleting a database takes a final snapshot.** Every DB instance and DB cluster sets `skip_final_snapshot` false and a non-empty `final_snapshot_identifier`. |
| RDS-004 | `data/rds_004.rego` | **Snapshots carry the database's tags.** Every DB instance and DB cluster sets `copy_tags_to_snapshot` true. |
| RDS-005 | `data/rds_005.rego` | **Database storage is encrypted with the stack key.** Every DB instance and DB cluster sets `storage_encrypted` true with `kms_key_id` the ARN of this stack's KMS key. |
| RDS-006 | `data/rds_006.rego` | **Databases accept only TLS connections.** A MySQL or MariaDB instance's DB parameter group (`parameter_group_name`, an `aws_db_parameter_group` of this stack) sets `require_secure_transport` to `1`/`ON`; a PostgreSQL instance's sets `rds.force_ssl` to `1`. Aurora clusters: the same parameters in their `aws_rds_cluster_parameter_group` (`db_cluster_parameter_group_name`). |
| SEC-001 | `data/sec_001.rego` | **Secrets are encrypted with the stack key.** Every Secrets Manager secret sets `kms_key_id` to this stack's KMS key (any form), not the AWS managed key. |
| SEC-002 | `data/sec_002.rego` | **Deleted secrets stay recoverable.** Every secret's `recovery_window_in_days` is between `7` and `30` (0 deletes without recovery). |
| IAM-001 | `iam/iam_001.rego` | **Identity policies name explicit actions.** Allow statements of identity policies (`aws_iam_policy`, `aws_iam_role_policy`, `aws_iam_user_policy`, `aws_iam_group_policy` and a role's `inline_policy` blocks) never use `NotAction` and never grant `*` or a whole service (`<service>:*`); they name the actions. |
| POL-001 | `iam/pol_001.rego` | **Every policy document is known at plan time and is valid JSON.** Every policy document CI reads (identity policies, trust policies, bucket, queue, topic, key, repository and secret policies, lifecycle policies) is known when the plan is made and is valid JSON. A document that is only known after apply cannot be checked, so it fails. A new topic, queue or key that leaves its policy to AWS is the exception. |
| KMS-001 | `kms/kms_001.rego` | **Customer managed keys rotate.** Every `aws_kms_key` has `enable_key_rotation` true, and a `rotation_period_in_days`, when set, of at most `365` days. |
| KMS-002 | `kms/kms_002.rego` | **Keys keep a long deletion window.** Every `aws_kms_key` has a `deletion_window_in_days` of at least `30`. |
| CW-001 | `logging/cw_001.rego` | **Alarms notify this stack's topics.** Every metric alarm lists at least one SNS topic of this stack in `alarm_actions`, and every SNS topic in `alarm_actions` is a topic of this stack (other actions, such as scaling policies, are fine). |
| LOG-001 | `logging/log_001.rego` | **Log groups keep events for a bounded period.** Every log group sets `retention_in_days` between `90` and `731` days, and a log group whose name ends in ``-audit`` between `365` and `731` days. 0 (never expire) is not allowed. |
| LOG-002 | `logging/log_002.rego` | **Log groups are encrypted with the stack key.** Every log group sets `kms_key_id` to the ARN of this stack's KMS key (CloudWatch Logs takes only the key ARN). |
| SNS-001 | `messaging/sns_001.rego` | **Topics are encrypted with the stack key.** Every topic sets `kms_master_key_id` to this stack's KMS key (key ARN, key ID, alias name or alias ARN). |
| SQS-001 | `messaging/sqs_001.rego` | **Queues are encrypted with the stack key.** Every queue sets `kms_master_key_id` to this stack's KMS key (key ARN, key ID, alias name or alias ARN). SQS-managed encryption (`sqs_managed_sse_enabled`) does not satisfy this rule. |
| SQS-002 | `messaging/sqs_002.rego` | **Work queues redrive to their own dead-letter queue.** Every queue whose name does not end in ``-dlq`` has a `redrive_policy` whose `deadLetterTargetArn` is the ARN of the queue named `<its name>`-dlq`` (of this stack) and whose `maxReceiveCount` is between `3` and `10`. |
| SQS-006 | `messaging/sqs_006.rego` | **One policy per queue.** A queue is the target of at most one `aws_sqs_queue_policy`: two would overwrite each other on every apply. |
| LB-001 | `network/lb_001.rego` | **Load balancers drop invalid headers.** Every application load balancer sets `drop_invalid_header_fields` true. |
| LB-002 | `network/lb_002.rego` | **Load balancers log every request.** Every application load balancer has `access_logs` enabled, delivered to a bucket of this stack whose bucket policy allows the Elastic Load Balancing log delivery principal of `us-east-1` (AWS `arn:aws:iam::127311923021:root`, or Service `logdelivery.elasticloadbalancing.amazonaws.com`) `s3:PutObject` on the objects the load balancer writes (`<bucket ARN>/<prefix>/AWSLogs/<account>/elasticloadbalancing/...`). |
| LB-003 | `network/lb_003.rego` | **HTTPS listeners use current TLS policies.** Every HTTPS or TLS listener uses one of the SSL policies `ELBSecurityPolicy-TLS13-1-2-2021-06`, `ELBSecurityPolicy-TLS13-1-2-Res-2021-06`, `ELBSecurityPolicy-TLS13-1-3-2021-06`. |
| LB-004 | `network/lb_004.rego` | **HTTP listeners only redirect to HTTPS.** Every HTTP listener has exactly one default action: a `redirect` to protocol `HTTPS` with status code `HTTP_301`. |
| LB-005 | `network/lb_005.rego` | **Load balancers are protected from deletion.** Every load balancer sets `enable_deletion_protection` true. |
| NET-001 | `network/net_001.rego` | **Nothing is reachable from the whole internet.** No ingress rule (inline `ingress` of an `aws_security_group`, `aws_security_group_rule` of type ingress, or `aws_vpc_security_group_ingress_rule`) admits `0.0.0.0/0` or `::/0`, except TCP ports (none) (single-port rules) on a security group attached to an internet-facing load balancer. |
| NET-002 | `network/net_002.rego` | **Every VPC records its traffic.** Every VPC has an `aws_flow_log` with `traffic_type` `ALL` whose destination type is one of `s3`, `cloud-watch-logs`. For `s3`: `log_destination_type` `s3` and `log_destination` the ARN of a bucket of this stack (optionally followed by `/<prefix>/`), whose bucket policy allows the service principal `delivery.logs.amazonaws.com` `s3:PutObject` on the objects flow logs write (`<bucket ARN>/<prefix>/AWSLogs/<account>/vpcflowlogs/<region>/...`) and `s3:GetBucketAcl` on the bucket ARN. For `cloud-watch-logs`: `log_destination_type` `cloud-watch-logs`, `log_destination` the ARN of a log group of this stack (with or without `:*` at the end) and `iam_role_arn` the ARN of a role of this stack, both known when the plan is made (a log group or role the plan creates has no ARN yet). |
| NET-006 | `network/net_006.rego` | **Network ACLs keep administrative ports closed to the internet.** No network ACL ingress entry with action `allow` admits `0.0.0.0/0` or `::/0` on TCP ports `22`, `3389` (or on every protocol): inline `ingress` blocks of an `aws_network_acl`, or `aws_network_acl_rule` with `egress` false. |
| S3-000 | `s3/s3_000.rego` | **Bucket names are known at plan time.** Every `aws_s3_bucket` has a `bucket` name known when the plan is made (the bucket rules match settings to buckets by name). |
| S3-001 | `s3/s3_001.rego` | **Buckets block all public access.** Every bucket has an `aws_s3_bucket_public_access_block` (matched by its `bucket` argument) with `block_public_acls`, `block_public_policy`, `ignore_public_acls` and `restrict_public_buckets` all true. |
| S3-003 | `s3/s3_003.rego` | **Bucket policies deny requests without TLS.** Every bucket has an `aws_s3_bucket_policy`, and its policy has a statement with Effect `Deny`, Principal `"*"`, Action `"s3:*"`, Resource both the bucket ARN and the bucket ARN followed by `/*`, and Condition `{"Bool": {"aws:SecureTransport": "false"}}`. |
| S3-004 | `s3/s3_004.rego` | **Buckets keep object versions.** Every bucket has an `aws_s3_bucket_versioning` whose `versioning_configuration` status is `Enabled`. |
| S3-006 | `s3/s3_006.rego` | **Bucket ACLs are disabled.** Every bucket has an `aws_s3_bucket_ownership_controls` whose rule sets `object_ownership` to `BucketOwnerEnforced`. |
| S3-007 | `s3/s3_007.rego` | **One resource of each setting type per bucket.** A bucket is configured by at most one resource of each settings type (`aws_s3_bucket_public_access_block`, `aws_s3_bucket_server_side_encryption_configuration`, `aws_s3_bucket_versioning`, `aws_s3_bucket_ownership_controls`, `aws_s3_bucket_policy`, `aws_s3_bucket_logging`, `aws_s3_bucket_lifecycle_configuration`): two would overwrite each other on every apply. |
| SAFE-001 | `safety/safe_001.rego` | **No resource is destroyed or replaced.** No resource change in the plan includes a `delete` action: a recorded resource is never destroyed, and never replaced (destroyed and re-created in either order). |
| SAFE-002 | `safety/safe_002.rego` | **No resource is forgotten.** No resource change in the plan is a `forget` (a `removed` block that keeps the object but stops managing it). |
| SAFE-003 | `safety/safe_003.rego` | **No resource moves to a new address.** No resource change in the plan has a `previous_address`: resources keep the addresses they have. |

The platform also runs deploy-stage guardrails on every production plan after CI; `GUARDRAILS.md` specifies them (CI does not run them).

CI loads the team's exceptions register (`exceptions/register.json`) as data; `EXCEPTIONS.md` says which findings a valid entry may waive.
