The cats-versus-dogs `dev` platform runs from Terraform in `/workspace/terraform` (local modules `network`, `platform`, `services` and `observability`; `terraform.tfstate` is production). The platform team already bulk-imported every production resource into stack `dev` of the Pulumi project `cats-vs-dogs` in `/workspace/pulumi`, but its entry point `index.ts` declares nothing, so a preview would delete everything. We need the TypeScript program, without changing anything deployed.

Each module call is one `pulumi.ComponentResource` under the stack, named after the module and typed `cats:modules:Network`, `cats:modules:Platform`, `cats:modules:Services` or `cats:modules:Observability`. Each Terraform resource instance is exactly one `@pulumi/aws` resource of the type the stack holds, under its module's component, named after the Terraform resource plus `-<key>` for `for_each` instances (`nat-us-east-1a`); nothing else is declared. Each variable in `variables.tf` is a same-named config key (`cats-vs-dogs:project`, ...) holding its value as plain YAML (integers, strings, booleans, mappings with Terraform's attribute names), and unset keys take the Terraform default. For any values Terraform and AWS accept, `pulumi preview` plans the same creates, updates, replacements, deletions and settings as `terraform plan`, and reverts drift as Terraform would. Values Terraform reads from another resource come from its output (unknown exactly where the plan shows known after apply), and what Terraform leaves unset stays unset, even if the imported state shows an AWS-filled value. Lists and strings built from map keys use sorted key order, and later maps win in `merge()`. Stack outputs match `outputs.tf`. Use only the default `aws` provider, with no `protect`, `ignoreChanges`, `retainOnDelete`, `deletedWith`, `import`, `aliases`, `replaceOnChanges`, `replaceWith`, `customTimeouts`, `transforms`, `hooks`, `provider` or `providers` option (not even false or default ones), and no stack or invoke transforms, resource hooks, remote components, `.get()` lookups, `StackReference`s or provider functions like `aws.getRegion()`. Production-generated IDs, ARNs, account ID, IPs and DNS names come from their owning resources and never appear in `/workspace/pulumi`, even split, reversed or encoded; constants from the Terraform code are fine.

Keep the production preview clean, `npx tsc --noEmit` passing, each preview under 300 seconds, and `Pulumi.yaml`, `Pulumi.dev.yaml`, `package.json` and `tsconfig.json` byte for byte (undo any `pulumi config set`; `/workspace` is a git repository). The program must run from the UTF-8 text files in `/workspace/pulumi` alone, with no symlinks and no reads outside. There's no AWS access, but `pulumi preview --refresh=false` works offline (backend `/workspace/pulumi-state` and passphrase preset), `pulumi stack export` shows every URN, and `terraform plan -refresh=false` runs offline in `/workspace/terraform`, also with `-var`/`-var-file`. `node_modules` links to the image's packages (Node.js 22, versions per `package.json`; `@pulumi/aws` 6.83.0 is built on Terraform's AWS provider 5.100.0); nothing can be installed.
