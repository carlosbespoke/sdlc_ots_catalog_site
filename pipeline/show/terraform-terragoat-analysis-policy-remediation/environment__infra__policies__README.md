# Platform policy pack

OPA/Rego rules that conftest evaluates on the JSON form of a Terraform plan (`terraform show -json`). Each rule is its own package (`rules.<id>`), so CI evaluates every package: `conftest test --all-namespaces --policy policies <plan.json>`. A rule reads the planned values of the resources the plan keeps, updates or creates (`resource_changes[].change.after`); a value that is only known after apply never satisfies a rule. `lib/tf.rego` holds the helpers the rules share (how resources, KMS key references, bucket settings, queue policies, role permissions and security group rules are found).

Conventions used by the rules:

- *This stack's KMS key* is a customer managed key (`aws_kms_key`) managed in the same plan, named by its ARN, its key ID, or the name or ARN of one of its aliases (`aws_kms_alias`), except where a rule asks for the key's ARN.
- *Of this stack* means managed in the same plan. Bucket settings resources (`aws_s3_bucket_*`) belong to the bucket named in their `bucket` argument, queue policies to the queue whose URL is their `queue_url`, a role's permissions are its inline policies plus the policies attached to it.
- Policy documents are read as JSON; one that is not known when the plan is made fails `POL-001`.

| Rule | File | Requirement |
|---|---|---|
| ASG-001 | `compute/asg_001.rego` | **Auto Scaling groups propagate the cost tags.** Every Auto Scaling group has a `tag` block with `propagate_at_launch` true for each of the tag keys `CostCenter`, `Owner`, so the instances it launches carry them. |
| EC2-004 | `compute/ec2_004.rego` | **Volumes use current-generation storage.** Every EBS volume of a launch template (`block_device_mappings` `ebs` `volume_type`) and every instance root volume (`root_block_device` `volume_type`) uses one of the volume types `gp3`. |
| EC2-005 | `compute/ec2_005.rego` | **Detailed monitoring is on.** Every instance sets `monitoring` true, and every launch template sets `monitoring` with `enabled` true. |
| EC2-006 | `compute/ec2_006.rego` | **Instances use approved instance types.** Every instance's `instance_type`, and the `instance_type` of every launch template that sets one, matches one of the patterns `t3.*`, `t3a.*`, `m6i.*`, `m7i.*`, `c6i.*`, `c7i.*`, `r6i.*` (`*` matches any run of characters). |
| LMB-001 | `compute/lmb_001.rego` | **Functions use active tracing.** Every Lambda function sets `tracing_config` with `mode` `Active`. |
| LMB-003 | `compute/lmb_003.rego` | **Functions log to a log group of this stack.** Every Lambda function writes its logs to a log group this stack manages: its `logging_config` `log_group` is the name of an `aws_cloudwatch_log_group` of this stack, or (without a `log_group`) the stack manages the group `/aws/lambda/<function_name>`. |
| LMB-005 | `compute/lmb_005.rego` | **A function's role allows what its configuration needs.** The execution role (`role`) of every Lambda function, through its inline policies, the customer managed policies of this stack attached to it, or the AWS managed policies AWSXRayDaemonWriteAccess, AWSLambdaBasicExecutionRole, AWSLambdaVPCAccessExecutionRole or AWSLambdaSQSQueueExecutionRole attached to it, allows: `xray:PutTraceSegments` and `xray:PutTelemetryRecords` when tracing is Active; `logs:CreateLogStream` and `logs:PutLogEvents` on the streams of the log group named in `logging_config` (`<group ARN>:log-stream:*`); `sqs:SendMessage` on a dead-letter queue (or `sns:Publish` on a dead-letter topic) named in `dead_letter_config`. |
| DDB-004 | `data/ddb_004.rego` | **Tables use the approved billing mode.** Every DynamoDB table uses a `billing_mode` in `PAY_PER_REQUEST`. |
| ECR-003 | `data/ecr_003.rego` | **Repositories expire old images.** Every ECR repository has an `aws_ecr_lifecycle_policy` (matched by `repository` name) whose policy has at least one rule with action type `expire`. |
| RDS-004 | `data/rds_004.rego` | **Snapshots carry the database's tags.** Every DB instance and DB cluster sets `copy_tags_to_snapshot` true. |
| RDS-008 | `data/rds_008.rego` | **Databases export their logs to CloudWatch Logs.** Every DB instance and DB cluster exports, in `enabled_cloudwatch_logs_exports`, at least the log types its engine requires: `mysql`: `error`, `slowquery`; `mariadb`: `error`, `slowquery`; `postgres`: `postgresql`; `aurora-mysql`: `error`, `slowquery`; `aurora-postgresql`: `postgresql`. |
| RDS-011 | `data/rds_011.rego` | **Databases are not publicly accessible.** No DB instance or cluster instance sets `publicly_accessible` true. |
| RDS-012 | `data/rds_012.rego` | **Database storage uses current-generation volumes.** Every DB instance with its own storage uses a `storage_type` in `gp3`, `io1`, `io2`. |
| POL-001 | `iam/pol_001.rego` | **Every policy document is known at plan time and is valid JSON.** Every policy document CI reads (identity policies, trust policies, bucket, queue, topic, key, repository and secret policies, lifecycle policies) is known when the plan is made and is valid JSON. A document that is only known after apply cannot be checked, so it fails. A new topic, queue or key that leaves its policy to AWS is the exception. |
| KMS-004 | `kms/kms_004.rego` | **Key policies grant the AWS services that use the key.** The key policy of every customer managed key grants, by service principal, the actions each AWS service needs for the resources of this stack that make it use the key: CloudWatch Logs (`logs.<region>.amazonaws.com`: kms:Encrypt, kms:Decrypt, kms:ReEncryptFrom, kms:ReEncryptTo, kms:GenerateDataKey, kms:DescribeKey) when a log group is encrypted with it; CloudWatch (`cloudwatch.amazonaws.com`: kms:Decrypt, kms:GenerateDataKey) when an alarm notifies a topic encrypted with it; a service that delivers to a queue or topic encrypted with it (kms:Decrypt, kms:GenerateDataKey): `sns.amazonaws.com` for SQS subscriptions of SNS topics, `events.amazonaws.com` for EventBridge targets (and dead-letter queues), `s3.amazonaws.com` for bucket notifications, and any of these three that a queue policy lets send to such a queue; VPC flow log delivery (`delivery.logs.amazonaws.com`: kms:Encrypt, kms:Decrypt, kms:GenerateDataKey) when flow logs go to a bucket whose default encryption uses it. |
| KMS-006 | `kms/kms_006.rego` | **Every key has an alias.** Every customer managed key is the target of at least one `aws_kms_alias` of this stack. |
| CW-001 | `logging/cw_001.rego` | **Alarms notify this stack's topics.** Every metric alarm lists at least one SNS topic of this stack in `alarm_actions`, and every SNS topic in `alarm_actions` is a topic of this stack (other actions, such as scaling policies, are fine). |
| CW-002 | `logging/cw_002.rego` | **Owned alarms notify their owner's topic.** An alarm tagged with one of `Service` notifies its owner: its `alarm_actions` include the SNS topic of this stack that carries the same tag with the same value. |
| CW-003 | `logging/cw_003.rego` | **Alarms also report recovery.** Every SNS topic in an alarm's `alarm_actions` is also in its `ok_actions`. |
| CW-004 | `logging/cw_004.rego` | **Every dead-letter queue has a backlog alarm.** Every queue whose name ends in ``-dlq`` is watched by a metric alarm with `namespace` `AWS/SQS`, `metric_name` `ApproximateNumberOfMessagesVisible`, a `QueueName` dimension equal to the queue's name, `comparison_operator` `GreaterThanThreshold` with a `threshold` below 1 (or `GreaterThanOrEqualToThreshold` with a threshold of at most 1), and at least one SNS topic of this stack in `alarm_actions`. |
| CW-005 | `logging/cw_005.rego` | **Every function has an error alarm.** Every Lambda function is watched by a metric alarm with `namespace` `AWS/Lambda`, `metric_name` `Errors`, a `FunctionName` dimension equal to the function's name, and at least one SNS topic of this stack in `alarm_actions`. |
| LOG-001 | `logging/log_001.rego` | **Log groups keep events for a bounded period.** Every log group sets `retention_in_days` between `180` and `545` days, and a log group whose name ends in ``-audit`` between `365` and `545` days. 0 (never expire) is not allowed. |
| LOG-002 | `logging/log_002.rego` | **Log groups are encrypted with the stack key.** Every log group sets `kms_key_id` to the ARN of this stack's KMS key (CloudWatch Logs takes only the key ARN). |
| SNS-001 | `messaging/sns_001.rego` | **Topics are encrypted with the stack key.** Every topic sets `kms_master_key_id` to this stack's KMS key (key ARN, key ID, alias name or alias ARN). |
| SNS-002 | `messaging/sns_002.rego` | **Topic policies do not open topics to everyone.** An Allow statement of a topic's policy that names every principal (`"*"` or `{"AWS": "*"}`) must carry a `StringEquals` condition on `aws:SourceOwner`, `AWS:SourceOwner` or `aws:SourceAccount` whose value is this stack's account. The topic's policy is the `aws_sns_topic_policy` that names it when there is one, else the topic's own `policy`. |
| SQS-001 | `messaging/sqs_001.rego` | **Queues are encrypted with the stack key.** Every queue sets `kms_master_key_id` to this stack's KMS key (key ARN, key ID, alias name or alias ARN). SQS-managed encryption (`sqs_managed_sse_enabled`) does not satisfy this rule. |
| SQS-006 | `messaging/sqs_006.rego` | **One policy per queue.** A queue is the target of at most one `aws_sqs_queue_policy`: two would overwrite each other on every apply. |
| LB-002 | `network/lb_002.rego` | **Load balancers log every request.** Every application load balancer has `access_logs` enabled, delivered to a bucket of this stack whose bucket policy allows the Elastic Load Balancing log delivery principal of `us-east-1` (AWS `arn:aws:iam::127311923021:root`, or Service `logdelivery.elasticloadbalancing.amazonaws.com`) `s3:PutObject` on the objects the load balancer writes (`<bucket ARN>/<prefix>/AWSLogs/<account>/elasticloadbalancing/...`). |
| NET-001 | `network/net_001.rego` | **Nothing is reachable from the whole internet.** No ingress rule (inline `ingress` of an `aws_security_group`, `aws_security_group_rule` of type ingress, or `aws_vpc_security_group_ingress_rule`) admits `0.0.0.0/0` or `::/0`, except TCP ports `80`, `443` (single-port rules) on a security group attached to an internet-facing load balancer. |
| NET-002 | `network/net_002.rego` | **Every VPC records its traffic.** Every VPC has an `aws_flow_log` with `traffic_type` `ALL` whose destination type is one of `s3`, `cloud-watch-logs`. For `s3`: `log_destination_type` `s3` and `log_destination` the ARN of a bucket of this stack (optionally followed by `/<prefix>/`), whose bucket policy allows the service principal `delivery.logs.amazonaws.com` `s3:PutObject` on the objects flow logs write (`<bucket ARN>/<prefix>/AWSLogs/<account>/vpcflowlogs/<region>/...`) and `s3:GetBucketAcl` on the bucket ARN. For `cloud-watch-logs`: `log_destination_type` `cloud-watch-logs`, `log_destination` the ARN of a log group of this stack (with or without `:*` at the end) and `iam_role_arn` the ARN of a role of this stack, both known when the plan is made (a log group or role the plan creates has no ARN yet). |
| NET-003 | `network/net_003.rego` | **Default security groups allow nothing.** Every VPC's default security group is managed by an `aws_default_security_group` (with that `vpc_id`) that has no `ingress` and no `egress` rules. |
| NET-004 | `network/net_004.rego` | **All-traffic ingress only from security groups.** An ingress rule that allows every protocol (`-1`) names only security groups (or `self`), never a CIDR range. |
| NET-005 | `network/net_005.rego` | **Only public subnets assign public IPs.** A subnet sets `map_public_ip_on_launch` true only when its ``Tier`` tag matches the regular expression ``^public$``. |
| S3-000 | `s3/s3_000.rego` | **Bucket names are known at plan time.** Every `aws_s3_bucket` has a `bucket` name known when the plan is made (the bucket rules match settings to buckets by name). |
| S3-001 | `s3/s3_001.rego` | **Buckets block all public access.** Every bucket has an `aws_s3_bucket_public_access_block` (matched by its `bucket` argument) with `block_public_acls`, `block_public_policy`, `ignore_public_acls` and `restrict_public_buckets` all true. |
| S3-002 | `s3/s3_002.rego` | **Buckets encrypt by default (SSE-KMS with the stack key; SSE-S3 where log delivery requires it).** Every bucket has an `aws_s3_bucket_server_side_encryption_configuration` whose every rule uses `sse_algorithm` `aws:kms` with `kms_master_key_id` set to this stack's KMS key; when `require_bucket_key` is true (it is `true` in this pack) each such rule also sets `bucket_key_enabled` to true. Exception: a bucket that receives load balancer access logs (an `aws_lb` `access_logs` block names it) or S3 server access logs (an `aws_s3_bucket_logging` names it as `target_bucket`) must use SSE-S3 (`sse_algorithm` `AES256`) instead, because those log delivery services support no other default encryption. Only log buckets may receive such logs: a bucket that receives them must have a name matching the regular expression ``archive``, or it fails this rule. |
| S3-003 | `s3/s3_003.rego` | **Bucket policies deny requests without TLS.** Every bucket has an `aws_s3_bucket_policy`, and its policy has a statement with Effect `Deny`, Principal `"*"`, Action `"s3:*"`, Resource both the bucket ARN and the bucket ARN followed by `/*`, and Condition `{"Bool": {"aws:SecureTransport": "false"}}`. |
| S3-007 | `s3/s3_007.rego` | **One resource of each setting type per bucket.** A bucket is configured by at most one resource of each settings type (`aws_s3_bucket_public_access_block`, `aws_s3_bucket_server_side_encryption_configuration`, `aws_s3_bucket_versioning`, `aws_s3_bucket_ownership_controls`, `aws_s3_bucket_policy`, `aws_s3_bucket_logging`, `aws_s3_bucket_lifecycle_configuration`): two would overwrite each other on every apply. |
| S3-008 | `s3/s3_008.rego` | **Buckets record server access logs in a log bucket of this stack.** Every bucket that does not itself receive server access logs has an `aws_s3_bucket_logging` whose `target_bucket` is another bucket of this stack, and the target bucket's policy allows the service principal `logging.s3.amazonaws.com` `s3:PutObject` on the objects S3 writes there (`<target bucket ARN>/<target_prefix><date>-<unique id>`, or with a partitioned `target_object_key_format` `<target_prefix><account>/<region>/<source bucket>/<yyyy>/<mm>/<dd>/...`). A bucket that receives the server access logs of other buckets (another bucket's `aws_s3_bucket_logging` names it as `target_bucket`) is exempt. |
| S3-009 | `s3/s3_009.rego` | **Buckets expire noncurrent versions and abandoned uploads.** Every bucket has an `aws_s3_bucket_lifecycle_configuration` with Enabled rules that apply to the whole bucket (no filter, or a filter with an empty prefix and nothing else) and that together expire noncurrent object versions within `60` days (`noncurrent_version_expiration` `noncurrent_days` at most `60`) and abort incomplete multipart uploads within `5` days (`abort_incomplete_multipart_upload` `days_after_initiation` at most `5`). |
| SAFE-001 | `safety/safe_001.rego` | **No resource is destroyed or replaced.** No resource change in the plan includes a `delete` action: a recorded resource is never destroyed, and never replaced (destroyed and re-created in either order). |
| SAFE-002 | `safety/safe_002.rego` | **No resource is forgotten.** No resource change in the plan is a `forget` (a `removed` block that keeps the object but stops managing it). |
| SAFE-003 | `safety/safe_003.rego` | **No resource moves to a new address.** No resource change in the plan has a `previous_address`: resources keep the addresses they have. |
| TAG-001 | `tagging/tag_001.rego` | **Resources carry the required tags.** Every resource that supports tags carries a non-empty value for each of the tag keys `Owner`, `CostCenter` (in its `tags_all`, the tags it ends up with). |
| TAG-002 | `tagging/tag_002.rego` | **Tag values follow the conventions.** Wherever a resource carries one of these tags (in `tags_all`), its value matches the regular expression: `CostCenter`: `^CC-[0-9]{4}$`; `Environment`: `^(prod\|staging\|dev)$`. |
